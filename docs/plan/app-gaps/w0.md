Shared rules for every lane in this wave.

  say so in your report instead of editing it.

## Lane 1 — shell children outlive crust

`src/plugins/shell.ts`, `src/app.ts`, and a test file of your own.

The plugin kills a child only when the page calls `shell.kill` (`shell.ts:176`). `app.quit()` closes
windows and stops the pump (`app.ts:177-184`) and never touches spawned children, so every running
`shell.spawn` outlives the app — and a `crust dev` restart is a SIGTERM the same code path never sees.

Decide and justify the mechanism: a registry in the plugin plus a synchronous `process.on("exit")` reap,
a `SIGTERM`/`SIGINT` handler, or a teardown the app calls. Requirements:

- Quitting kills children; `SIGTERM` does too, because that is how `crust dev` restarts.
- Never delay the quit: the app's exit path already flushes the logger asynchronously, so a synchronous
  reap is the only shape that cannot hang.
- A child that ignores TERM is escalated, but the app does not wait forever.
- A test spawns a real long-lived process, quits the app, and asserts the child is gone by pid.

State in the report whether `sidecar` has the same defect (read it; do not fix it here).

## Lane 2 — the updater cannot follow GitHub Releases

`src/plugins/updater-fetch.ts` (and its test), `site/app/docs/guides/updater/page.mdx`,
`site/app/docs/guides/release/page.mdx`.

`updater-fetch.ts:42-56` refuses every 3xx, and `https://github.com/…/releases/latest/download/…` is a
302 — so the most obvious host for a feed cannot work, while the docs present it as the normal case.

- Follow bounded https→https redirects (5 hops, then refuse), and refuse any downgrade to http.
- The security boundary is the pinned Ed25519 `updater.pubkey` over the artefact bytes, not the host —
  say that in the code comment, because following a redirect looks like loosening pinning.
- Do not add auth headers for private repos; the docs already say "unguessable path + pinned key".
- Correct `guides/release:70` where it says one JSON per version; the pubkey is what never changes.
- Test: 302 to https followed, 302 to http refused, a redirect loop stops at the bound.

## Lane 3 — three CSP defects, one of which made voice look framework-blocked

`src/bridge/server/csp.ts`, `src/single-detect.ts`, `src/cli/dev.ts`, and one new docs page
`site/app/docs/guides/network/page.mdx` plus its `site/lib/nav.ts` entry.

1. `DEFAULT_CSP` (`csp.ts:15-23`) has no `media-src`, so `blob:` audio/video is refused by spec. Add
   `media-src 'self' blob:` — a page that records must be able to play back what it recorded.
2. A single-file app's config (`single-detect.ts:96-116`) carries only `app` and `windows`, so it can
   never set `security` — no CSP override, no grants, no microphone. Give it a security field, chosen
   from whatever the single-file module can declare, and say what the trade-off is.
3. Dev serves no crust CSP while a built app does (`dev.ts:87-95`), which is why an external provider
   call works in dev and fails after build. Either serve a matching policy in dev or make the asymmetry
   impossible to miss; state which and why.

The docs page must answer, with the real config: how a page reaches an external HTTPS/WSS service, what
`security.csp` replaces, what microphone needs, and what dev does differently.
