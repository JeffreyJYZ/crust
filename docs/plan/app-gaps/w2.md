# Wave 2 briefs: pty, preview, browser — three lanes, disjoint files

Wave 1 landed the config sections, the plugin names and the capability actions. Each lane below owns its
own plugin module, its own platform half and its own tests; none edits `src/runtime-plugins.ts`,
`src/config/types.ts`, `src/app-types.ts`, `site/lib/nav.ts` or another lane's shim unit.

Shared rules: `rg`/`fd` only, `sd` never `sed`, no `bun fmt` without a path list, 200-line cap (split,
never trim), push as `jyzbot`, open a PR, do not merge, report under 12 lines with the proof line.

## A — pty (`src/plugins/pty*.ts`, `src/platform/windows/shim/63_pty.c`)

Bun 1.4.5 ships `Bun.Terminal` on POSIX, measured in recon (`docs/recon/app-gaps/03-terminal.md`): no
FFI, no `openpty`. Use it rather than hand-binding libc.

- Commands: `open({ program?, cols, rows })` answering a handle id, `write({ id, data })`, `resize`,
  `close`, `list`; events `pty-data` (bytes as base64, never a decoded string) and `pty-exit` (code).
- The plugin registers only when the `pty` config section exists, and `pty:open` is its own capability —
  never implied by `shell`. A page without the grant is refused with the same `forbidden` shape as `fs`.
- Reap through the same `child-reap` path wave 0 added, so a terminal cannot outlive `quit()` or SIGTERM.
- Windows: `CreatePseudoConsole` + `CreateProcessW` + two named pipes in a shim unit. If that cannot be
  proven in this lane, ship POSIX and have `pty.open` answer a named `not-implemented` on Windows rather
  than registering a surface that cannot work — and say so in the report.
- Proof: a real `bun` REPL or `sh` over the pty, a command typed in, its output arriving as `pty-data`,
  and the child gone after `close`. On Windows, the same through ConPTY or the named refusal.

## B — preview (`src/platform/darwin/preview.ts`, `shim/125_preview.c`, `src/plugins/preview.ts`)

`QLPreviewPanel` over the window, per recon (`04-office.md`): dynamic class + IMPs like the panels crust
already builds, a C-side path array, a sheet-style non-blocking poll.

- Command: `preview.show({ path, width?, height? })` and `preview.hide()`. Absolute path only, and the
  path must pass the same `fs.scope` containment `fs` uses — a preview is a file read.
- macOS: a floating panel over the window; the app still runs, keys go to the panel. Panel lifetime tied
  to the window that opened it: closing the window must not leave it floating.
- Windows/Linux: `preview.show` answers a named `not-implemented` with the reason (no embedded system
  preview API; `opener` exists for opening the file in its own app). Never silently open an external app
  from a command called `preview.show`.
- Proof: a real `.docx` from `/System/Library/QuickLook` or a fixture rendered by the panel (a screenshot
  through `window.capture` is acceptable evidence), `hide()` closing it, and the refusal on a path outside
  `fs.scope`.

## C — browser (`src/platform/darwin/browser.ts`, `shim/131_browser.c`, `src/plugins/browser.ts`)

An embedded webview inside a window, per recon (`02-browser.md`): a fresh `WKWebViewConfiguration`, an
`NSView` host added with the positioned insert the material view already uses, one frame setter, two
preflight entries. Navigation and load state are already per-webview.

- Commands: `open({ label, url, bounds })` (http/https only, origin must be in `browser.origins`),
  `navigate`, `state` (`loading`/`title`/`url`), `setBounds`, `close`.
- The surface has **no bridge token**: it loads remote content, so it must not be able to reach
  `window.crust`. `target=_blank` and `window.open` are refused and handed to `opener`.
- Install the capture denial on the surface, or any page can trip TCC for the whole app.
- Grant `browser:open` gates creating a surface; the origin allowlist gates what it loads.
- Proof: a local `Bun.serve` page inside one window, `state` reporting its title, `setBounds` moving it
  (screenshot through `window.capture`), and `open` on an origin outside `browser.origins` refused by name.
