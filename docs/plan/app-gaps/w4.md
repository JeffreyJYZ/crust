# Wave 4 brief: wire the feature halves, prove them, document them

The platform lanes deliberately stop before `src/runtime-feature-plugins.ts`: wave 1 left one stub factory
per feature, and pty replaces its own. This lane is the single writer for that file afterwards, so a
second feature can land without two branches editing the same switch.

## Wiring, one feature at a time

- **pty** — replace the refusing stub with `createPtyPlugin({ shell })`, only when `config.pty !== undefined`.
  The gate is already `sections.pty !== undefined`; nothing else changes.
- **preview** — always registered; its adapter is the platform's preview module. macOS has a panel, Windows
  may have a COM host by then, and every other platform answers `not-implemented` with the reason.
- **browser** — always registered; adapter is the platform's surface module, gated at call time by
  `browser.origins`. `browser:open` is the capability action; an origin not in the list is refused by name.

Each plugin must declare its commands so the generated `SKILL.md` table includes them; run
`bun run skill:check` and regenerate the table if the release script would.

## Proof, one e2e per feature

- `e2e:pty` — a real shell over the pty, a typed command, the output as `pty-data`, no child after `close`.
- `e2e:preview` — a real file in the panel, `hide()` closing it, and a path outside `fs.scope` refused.
- `e2e:browser` — a local `Bun.serve` page, `state` reading its title, `setBounds` moving it, and an origin
  outside `browser.origins` refused.

Each script follows the shape of `scripts/e2e-media.ts`: build a fixture app, launch under `probe-run`,
assert, print `PASS <name> <observed>`, exit non-zero on the first failure, and leave no process behind.

## Docs, and the honest platform split

- `guides/pty`, `guides/preview`, `guides/browser`: replace the "ships in 0.2.x" stub with the real config,
  the commands, the grant each needs, and a per-platform table.
- The preview page must say plainly that Linux has no embedded system preview and `opener` is the way.
- The browser page must say the surface has no bridge token and cannot call `window.crust`, and that
  `target=_blank` goes to `opener`.
- Parity page rows for all three; `SKILL.md` prose for `pty:open` (never implied by `shell`) and for the
  browser origin allowlist.
- `window.capture` on Linux was the honest gap; the WebKitGTK `webkit_web_view_get_snapshot` path now
  closes it, proved by the GTK smoke's `capture` step and the per-view adapter on both platforms.

## Rules

- `rg`/`fd` only, `sd` never `sed`, no `bun fmt` without a path list, 200-line cap.
- `bun run test`, `bun check`, `check:lines`, `site:build`, `check:links`, `check:parity`, `skill:check`,
  and each e2e you touched.
- Push as `jyzbot`, open a PR, do not merge. Report the e2e output lines, not a summary of them.
