# plugin-barrel lane memory

- **Slice**: split `src/plugins/index.ts` by area so the plugin surface can keep growing, audit plugin registration against `src/runtime-plugins.ts`, and add a barrel contract test.
- **Files**: `src/plugins/index.ts` (18), `src/plugins/barrel-core.ts` (24), `src/plugins/barrel-platform.ts` (52), `src/plugins/barrel-data.ts` (45), `src/plugins/barrel-system.ts` (96), `src/plugins/barrel.test.ts` (123).
- **Measured before the split**: `src/plugins/index.ts` was 195 lines of a 200-line cap, and `bun -e 'Object.keys(await import("./src/plugins/index.ts")).length'` answered 81 value exports.
- **Measured after the split**: the same call answers 81, with 0 gone and 0 added; source-level `export { … } from` blocks carried 183 names before and 181 across the four barrels, the other two being `corePlugins`/`coreRegistry` re-exported straight from `./core` in `index.ts`.
- **Decision**: `index.ts` re-exports each area with `export *` rather than repeating 183 names, matching the repo's own convention in `src/config/index.ts` and `src/app.ts`.
- **Trap**: an ambiguous `export *` (the same name in two areas) does **not** error — ESM drops that name from the namespace, so the import silently stops existing.
- **Consequence**: `barrel.test.ts` is the guard against that, not a formality — it lists all 81 value exports and asserts each is present and not `undefined`.
- **Decision**: the area split is core (mechanism), platform (native half), data (disk), system (app-level services); `i18n` sits in `barrel-system.ts` because it is an app-level service and belongs to none of the other three.
- **Note**: `windowStatePlugin` lives in `src/plugins/window-persist.ts`; the file name and the plugin name differ deliberately, so a rename there is a breaking change, not a tidy-up.
- **Registration, registered with its darwin adapter** (all in `nativePlugins`): `dialog`, `notification`, `tray`, `window`, `clipboard`, `opener`, `os`, `shortcuts`, `window-state`, `positioner`, `menu`, `theme`, `dock`, `power`, `accessibility`.
- **Registration, adapter-free but registered**: `fs` (scope passed via `createFsPlugin`), `autostart`, `logging`, `stronghold`, `store`, `shell`, `deep-link`, and `updater` only when the config has an `updater` section.
- **Registration outside `runtime-plugins.ts`**: `single-instance` is built by `claimSingleInstance` in `src/runtime-single.ts` and appended to the plugin list by `src/runtime.ts:85`, so it is reachable even though `runtime-plugins.ts` never names it.
- **Confirmed once each**: `dock`, `power`, `accessibility`, `theme`, `menu`, `positioner`, `window-state` appear exactly once in the darwin branch; the non-darwin branch filters `window` out of `core` before adding it, so no name repeats there either.
- **Gap, exported but never registered**: `i18n` — `createI18nPlugin` is exported and `darwinLocaleAdapter()` exists in `src/platform/darwin/locale.ts`, but no runtime module builds it, so `config.plugins: ["i18n"]` is the unknown-plugin error.
- **Gap, registered but adapter never wired**: `deep-link` is registered as `deepLink.plugin`, and nothing calls `installDeepLinkHandler`, `takeLaunchUrl` or `deepLink.launch`, so the darwin delegate is never installed and no scheme is ever registered.
- **Gap, darwin adapter exists but the plugin is neither exported nor registered**: `downloads` (`darwinDownloadsAdapter`), `network` (`darwinNetworkAdapter`), `navigation` (`darwinNavigationAdapter`), `findinpage` (`darwinFindAdapter`), `crash-reporter` (the `crashUnit`/`armCrashHandlers` half).
- **Not a gap**: `window-chrome` is not a plugin — `src/plugins/window-chrome.ts` is a command group and `windowChromeAdapter` is spread into `window`'s native adapter in `src/platform/darwin/window-adapter.ts:56`.
- **Not a gap**: `find`/`locale`/`network`/`downloads`/`navigation` darwin modules are adapters with no registration, so the fix is a plugin-list entry in `runtime-plugins.ts` plus the import, not new platform code.
- **Decision**: `runtime-plugins.ts` was not edited (out of slice); the exact change for `i18n` is a `const locale = await import("@/platform/darwin/locale")` beside the other darwin imports, `createI18nPlugin` added to the destructured `@/plugins` import, and `createI18nPlugin({ adapter: locale.darwinLocaleAdapter() })` appended to the returned array.
- **Trap**: `bun run test src/plugins` appends to the `test` script's own directory list, so it runs `src/bridge src/plugins src/platform src/cli src/packaging` — 104 files and 759 tests — and is not a scoped run.
- **Trap**: `bun check` over the whole tree was red from sibling lanes during this slice (`src/cli/commands.ts`, `src/cli/parse.ts`, `src/extensions/load.ts`), so the slice was proved green with `bun check <the six files>` — "No type errors in 70 files".
- **Trap**: `sed` is blocked in agent shells here, and `awk 'NR==109' file` is the read for one line when a diff looks wrong.
- **Gate result at hand-off**: `bun check <slice>` no type errors in 70 files, `bun run test src/plugins` 759 pass / 0 fail, `bun test src/plugins/barrel.test.ts` 3 pass, `bun run check:lines` PASS.
