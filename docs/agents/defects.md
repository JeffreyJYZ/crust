# defects lane — measured traps

- **FIXED — grants follow the token-bound label, not a request-body label.** `src/bridge/server/handler.ts:191` passes the token's label as `authority`; `src/bridge/server/invoke.ts:68-70` checks `capabilities.allows(authority, candidate)`, and routing only sets `ctx.window`. A page writing `"window": "admin"` addresses that window but cannot hold its grants. Keep the token-bound authority when touching the bridge; the old body-label bypass is why it exists.
- **FIXED — `updater.check` applies the same URL policy as `download`.** `src/plugins/updater-url.ts:2-3` declares the policy for both commands and `src/plugins/updater.ts:81-88` calls it before fetching. Any new fetch entry point must pass the same scheme check; the unpoliced check was the hole.
- **FIXED — `shell-env` folds both sides before comparing.** `src/plugins/shell-env.ts:24-31` lowercases the incoming name and prefix-matches `dyld_`, so lowercase `node_options` cannot bypass on case-insensitive Windows. Keep the fold when adding injection names.
- The mac keychain `list` shim uses a fixed `char small[256]` per account, so names over 255 bytes are silently absent from `list` though `get` finds them. A caller-side buffer re-read cannot fix a per-entry limit in C.
- Probe tests placed under `docs/reviews/next-wave/probes/` are collected by neither `bun test` (its script names explicit source paths) nor `bun check` (tsconfig includes only `src` and `scripts`). A red probe can stay there without reddening the gate.
- Run probes directly: `bun test docs/reviews/next-wave/probes/`. The capability probe needs `handlers: [testPlugin]` — `startBridge` throws on an empty handler map.
