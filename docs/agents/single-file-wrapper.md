# single-file-wrapper lane memory

- **Slice**: the two generated entries in `src/cli/build/wrapper.ts` and the single-file dev runner in `src/single-runner.ts`.
- **Closed 2026-11-16**: a single-file build's guard launch re-ran the app's module-level code. `singleWrapperSource` statically imported `src/index.ts`, called `registerSingleCommands` and added the quit listener at module top, and `startApp`'s marker check sits after all of it — so the guard process created the app singleton, registered both commands and added the listener a second time, in a process whose only job is to watch a pid.
- **Fix**: the guard's own module is the only static import, the marker check is the first statement, and the app side is four literal `await import(...)`s. Chosen over a generated prologue module because it keeps one generated file, needs no second path in `single-app.ts` or `build.ts`, and leaves every framework path as an absolute literal.
- **Measured**: `bun build --compile` bundles a literal `await import(...)` like any other — a two-module probe printed its imported value, with and without `--trim` (Bun 1.4.4).
- **Measured**: `crust build page.html` on the new shape gives 85.85 MiB, ad-hoc signed, and `CRUST_CRASH_GUARD=999999 CRUST_CRASH_GUARD_ROOT=… ./page.app/Contents/MacOS/crust-app` exits 0 in 0.97 s writing nothing — the guard path, never a window. An unmarked launch keeps running, so the exit is the short-circuit.
- **Not fixed, same hazard**: `wrapperSource` (the multi-file entry) statically imports the extension files and calls `registry.register(...)` before `startApp`, so an extension's module-level code also runs on a guard launch. The user's `main.ts` is safe — `entryModule` is invoked at `runtime.ts:155`, long after the check at `runtime.ts:40`. A fix means emitting dynamic imports from `src/extensions/entry-source.ts`, which is another lane's file.
- **Trap**: a test that writes generated modules with `\\n` escapes inside template literals alongside `${...}` substitutions can fail to parse in the host file — Bun 1.4.4 reported `Unterminated string literal` / `Expected "]"` at a line far from the real cause. Build the module bodies from `JSON.stringify(value)` and log space-separated names instead of escaping newlines by hand.
