# Lane C — the credential lives in a content world

- **`shim/121_content_world.c` + `content-world.ts`** — `+[WKContentWorld worldWithName:]` is resolved once per process; two `WKUserScript`s go on the window's controller at document start, one isolated (reads the token, opens the SSE stream, answers invokes) and one in the page world (`window.crustInvoke` only). Installed from `window-create.ts` before `shim_webview_load`.
- **A nil world faults, it does not throw** — `-initWithSource:…inContentWorld:` dereferences the world, so a bare 0 for the page world segfaults at `0x10` with no Objective-C exception (measured 2026-11-17, from `cc()` in the suite). Worlds are therefore resolved from an integer: `shim_content_world_named(0)` is `+[WKContentWorld pageWorld]`, `1` is the isolated world.
- **Only install when the document URL carries `?token=`** — a `crust dev` page gets `window.__CRUST__` from Vite and has none, so the install refuses and `installInvoke` keeps its fetch path. Nothing is half-installed: the isolated half fails first.
- **The two worlds share the DOM and nothing else**, so every message is a `CustomEvent` whose `detail` is a JSON string (`crust:req` / `crust:res` / `crust:sub` / `crust:evt`). A finished string is the only value that survives both worlds.
- **The token is absent three ways on the content-world path** — not in the URL (the isolated world calls `history.replaceState` at document start), not on `window.crust.token`, and not on `window.__CRUST__`. `installCrust` and the invoke half both branch on `typeof scope.crustInvoke`.
- **Honest limit**: page script can still call every granted command — that is the point. It cannot read the token nor replace the transport, and `fs:*` is still a file write.
- **No live GUI probe was run**: darwin has no `shim_webview_eval` (Linux does), so asserting `typeof window.crustInvoke` from outside the page needs an eval export that does not exist yet. The native half is proven by building a real `WKWebView` and registering both scripts; the round trip is proven in `src/bridge/client/content-world.test.ts`, which installs both scripts against a real bridge and a stub `document` whose only shared state is the event bus.
