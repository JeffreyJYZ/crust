# Native surface security review — wave 2

Scope: `downloads`, `network`, `crash-reporter`, `shell`, `fs` scope, `stronghold`, `extensions`, `updater`, read from source. Read-only; nothing but this file was touched.

## Reachability model (read this before the table)

- The only caller of a plugin is a script in the app's own page: the bridge admits `origin` + token (`src/bridge/server/handler.ts:73`, `src/bridge/server/cors.ts:35`), so third-party sites cannot reach it.
- Therefore every finding below is "one XSS, or one compromised page dependency, owns it", and the app page itself is not the attacker to defend against.
- `nativePlugins` mounts `fs`, `shell`, `downloads`, `network`, `crash-reporter` for every app; `updater` only when the config has an `updater` section (`src/runtime-plugins.ts:73`, `:180`, `:188`).

## Findings

| #   | Severity | Where                                                       | What an attacker controls                                                                                                                                                                                                                                   | Smallest fix                                                                                                                           |
| --- | -------- | ----------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | high     | `src/plugins/updater.ts:129` (`install`)                    | Both `path` and `appPath`. Any `.app` directory is renamed over any other `.app` directory, so a page installs its own bundle and the next launch runs it. Nothing is hashed or signed here.                                                                | Re-verify `sha256`/signature on `args.path` inside `install` before `replaceBundle`, and refuse a `path` outside the updater temp dir. |
| 2   | high     | `src/plugins/updater-signature.ts:72` (`readSignatureArgs`) | `pubkey` itself, whenever the config pins none — which is the default (`createUpdaterPlugin()` has no `options.pubkey`). `download` then verifies a signature against the attacker's own key, and `parseManifest` does the same (`updater-manifest.ts:33`). | Require `options.pubkey`; refuse `download`/`check` signature claims when none is pinned.                                              |
| 3   | high     | `src/plugins/updater.ts:95` (`download`)                    | `url` with no scheme restriction, and `sha256`/`signature` are optional. `{url}` alone returns `{ok:true, path}` for any fetched bytes, which feeds finding 1.                                                                                              | Make `sha256` mandatory and pin the URL to the configured endpoint's host.                                                             |
| 4   | high     | `src/plugins/shell.ts:101`                                  | The child's whole environment: `env` is spread over `process.env`, so `NODE_OPTIONS=--require …`, `GIT_EXEC_PATH`, `BASH_ENV`, `LD_PRELOAD` turn any allowlisted tool into arbitrary code execution and the allowlist into decoration.                      | Drop page-supplied `env`, or allow only names the app names explicitly.                                                                |
| 5   | medium   | `src/plugins/shell-args.ts:135`                             | The allowlist matches the **basename** of a path-form program, plus lexical containment in `cwdRoot` (default `process.cwd()`, `shell.ts:77`). A file named `node` written anywhere under the root runs as `node`.                                          | Compare the resolved `realpath` against an allowlist of absolute paths, not names.                                                     |
| 6   | medium   | `src/plugins/shell-args.ts:115` and `:138`                  | `cwd` and a relative program are contained by string prefix only, never `realpath`, so a symlink under `cwdRoot` moves both outside it. `fs.rename` (finding 7) can plant such a symlink from a Homebrew `bin` entry.                                       | `realpath` the resolved cwd and target before the containment test.                                                                    |
| 7   | medium   | `src/plugins/fs-scope.ts:105` and `src/plugins/fs.ts:178`   | Any absolute path at all: `enabled` is `allow !== undefined`, and the default registration passes no `allow`, so `check()` returns immediately. A page reads and writes every file the user can, including `~/.ssh`.                                        | Default `fs` to the app data dir and require an explicit opt-out for today's behaviour.                                                |
| 8   | medium   | `src/plugins/fs-scope.ts:143` (`allow`)                     | The scope itself: `fs.scopeAllow` is a page command that appends any path and persists it to `scope.json`, so the boundary is writable by the thing it bounds.                                                                                              | Take the grant from the host (config callback or a native consent sheet), not from a bridge command.                                   |
| 9   | medium   | `src/plugins/network.ts:45` (`patternMatches`)              | Case only: a block rule keyed on a lowercase host is bypassed by the same host in uppercase, because the whole URL is compared byte-wise while hosts are case-insensitive.                                                                                  | Lowercase the scheme and host of both pattern and URL before matching.                                                                 |
| 10  | medium   | `src/platform/darwin/shim/110_network.c:19` (`NET_TEXT`)    | The matched string: `net_copy` truncates the URL at 2047 bytes, so a tail-anchored rule (`*evil.example*`) never sees a match at the end of a long URL and the request is allowed.                                                                          | Fail closed when the URL does not fit: answer block instead of matching a prefix.                                                      |
| 11  | low      | `src/runtime-crash-store.ts:49`                             | Nothing directly, but `crashes.log` and `last-crash.json` are written with no `mode`, so they land `0644` and any local user reads the signal, `si_code`, fault address and timings — while the 0600 record beside them stays private.                      | Pass `{ mode: 0o600 }` to both writes.                                                                                                 |
| 12  | low      | `src/plugins/crash-reporter.ts:114` (`clear`)               | Crash evidence: `crash-reporter.clear` is a page command that deletes `crashes.log` and `last-crash.json`, so a page can erase the record of its own crash loop.                                                                                            | Gate `clear` behind a host-side call, or keep an append-only copy the bridge cannot delete.                                            |
| 13  | low      | `src/plugins/downloads-scope.ts:32`                         | Nothing by itself: `destination()` uses `resolve` (lexical) and never `realpath`, so a symlink already inside the data root is accepted as a destination and WebKit writes through it. No bridge command creates a symlink, so this needs one to pre-exist. | `realpath` the destination's existing ancestor before the containment test.                                                            |
| 14  | low      | `src/plugins/downloads.ts:46` (`uniquePath`)                | Timing: two downloads started before either file exists both see `existsSync === false` and get the same path, so the second overwrites the first.                                                                                                          | Reserve each answered path in a `Set` for the lifetime of the process.                                                                 |
| 15  | low      | `src/plugins/updater.ts:153` (`relaunch`)                   | Which bundle is launched: `isAppBundle` only checks a `.app` suffix and `isDirectory`, then `open -n <path>` runs it. Launching an already-installed app is not new code execution, but it is a page-driven process start.                                  | Restrict `relaunch` to the bundle the app itself occupies.                                                                             |
| 16  | low      | `src/plugins/stronghold-file.ts:65`                         | The KDF cost: `iterations` is read from the file with only `>= 1` validation, so a store file the user already owns can force a 1-round PBKDF2 (weakens nothing an attacker with write access needs) or an enormous one (app hangs on `open`).              | Clamp to `[100_000, 5_000_000]` and refuse outside it.                                                                                 |
| 17  | low      | `src/plugins/shell-args.ts:146`                             | Nothing new, but allowlisting `sh`, `bash`, `env`, `node` or `python` makes the list decorative: one allowlisted interpreter reaches every binary. Nothing warns the author.                                                                                | Refuse interpreters and shells in `allow` with a named error.                                                                          |
| 18  | medium   | whole surface, `src/runtime-plugins.ts:153`                 | Everything above at once: one capability set for one caller. There is no per-plugin grant, consent prompt or read-only mode, so an XSS in the page reaches app install, arbitrary file write and program spawn together.                                    | Ship a per-plugin capability list that the host opts into, defaulting to `fs`+`store` only.                                            |

## Checked and sound (do not re-review)

- `crash-record.bin` is opened `0600` (`shim/112_crash_install.c:33`, `:68`), and the handler writes with `write(2)` only — async-signal-safe, no allocation, no stdio.
- The crash guard's `--pid` and `--root` come from the runtime, never from a bridge command (`crash-reporter.ts:119`, `runtime-crash-guard.ts:75`); a page cannot point it at another pid or another root.
- `fs` canonicalises **before** comparing: `realpath` of the target, `realpath` of each prefix, then the prefix test (`fs-scope.ts:45`, `:135`), and a missing leaf resolves through its nearest existing parent.
- `fs.rename` checks both ends against the scope, so a rename cannot leak a file out of a prefix (`fs.ts:165`).
- `scope.json` is written `0600` through a temp file plus rename (`fs-scope.ts:89`).
- `stronghold.json` is written `0600` with an explicit `chmod` after the write and a rename (`stronghold-file.ts:107`).
- `stronghold` crypto is PBKDF2-SHA256 at 600 000 rounds over a 16-byte random salt, AES-256-GCM with a fresh 12-byte IV per seal, HMAC-SHA256 entry ids, and a sealed marker as the wrong-password oracle (`stronghold-crypto.ts:35`, `:67`, `:95`, `:117`).
- A failed `stronghold.open` leaves any existing session untouched — `session` is assigned only on success (`stronghold.ts:84`), so a wrong password cannot downgrade an unlocked store to a fresh one.
- `extensions` discovery reads only the top level of one directory and keeps `entry.isFile()`, so a symlink or a subdirectory is not imported (`load.ts:84`); `import()` runs only after `stat(file).isFile()` (`load.ts:115`).
- `extensions` `named()` does accept `..` and absolute paths (`load.ts:105`), but its input is the app's own config, not the page — not reachable by an attacker.
- `updater`'s download filename is sanitised to `[A-Za-z0-9._-]` with `.`/`..` refused, so a manifest URL cannot escape the temp dir (`updater-args.ts:168`).
- `updater.replaceBundle` restores the backup when the second rename fails, so a failed swap is not a half-installed app (`updater-node.ts:54`).
- `network`'s log is bounded at 100 entries with the oldest dropped (`network.ts:111`), and the matcher has no regex, so no backtracking.
- `network` rules only apply to URLs under `crust-net`; `http(s)` traffic is not intercepted at all, which is documented in `network-types.ts:8` — do not read the plugin as an egress firewall.
- `downloads` strips `/` and `\` from the suggested filename and never accepts a page-chosen absolute destination outside the data root (`downloads.ts:47`, `downloads-scope.ts:32`); `setDirectory` refuses a relative path and a `..` walk.
- The bridge refuses an absent `Origin` and any origin that is not its own or a configured dev origin, before the token is even read (`handler.ts:73`, `server.test.ts:53`).

## Observations, not findings

- `network`'s allow path cannot serve anything: an allowed task is fetched with `NSData dataWithContentsOfURL:` on a `crust-net` URL, which has no loader, so every allowed request fails `-1011` (`shim/110_network.c:93`). Functional gap, not a hole.
- `downloads.start` accepts any scheme, including `file:`. WebKit's own same-origin rules are expected to refuse a local file for an http page, but that was not proven here and no finding is claimed.
- `updater.check` fetches a page-supplied endpoint, which is a blind GET against loopback addresses; it returns a parse failure, never the body, so it is a port-scan primitive at most.
