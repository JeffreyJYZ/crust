# Packaging hunt

## High — Developer ID `crust sign` leaves declared sidecars ad-hoc-signed, so notarization rejects the bundle
- where: `src/cli/sign.ts:48-53`, `src/packaging/sign.ts:59-77`, `src/cli/build.ts:152-160`, `src/packaging/installers-sidecars.ts:56-72`
- mechanism: `crust build` signs each declared sidecar under `Contents/MacOS` ad-hoc (`codesign --sign -`). `crust sign` re-signs only the outer `.app` with the Developer ID identity, `--options runtime` and the JIT entitlement. `codesign` does not re-sign nested code unless `--deep` is passed — measured from local `man codesign` (lines 495-509: "Code nested within bundle directories must already be signed or the signing operation will fail, unless the `--deep` option is given"). The sidecars therefore keep `flags=0x2(adhoc)` and no hardened-runtime flag. Apple's notarization contract requires every nested executable to be Developer ID signed and hardened; `xcrun notarytool submit` rejects the whole submission. `codesign --verify --strict` still passes (it does not recurse into nested code by default), so the CLI reports success right up to `crust notarize`.
- reachable by: config sets `build.sidecars`, then `crust build` → `crust sign` with `CRUST_SIGNING_IDENTITY` → `crust notarize`. Any shipped app with a sidecar can never be notarized or pass Gatekeeper on a recipient machine.
- smallest fix: in `crust sign`, before `signApp`, re-sign each declared sidecar in `Contents/MacOS` with the same Developer ID identity and `--options runtime`; generalize `signSidecars` to take an identity/mode instead of its hardcoded `-`, and call it from both `crust build` and `crust sign`.

## Medium — `crust package` has no platform/format guard, so it can emit an artefact that never runs
- where: `src/cli/package.ts:30-56,92-97`, `src/cli/package/format.ts:6-18`, `src/cli/util.ts:151-166`, `src/cli/package/options.ts:40-67`
- mechanism: `parseFormats` accepts `dmg|appimage|nsis` on every host and `findBuildArtifact` returns whatever this host built. On macOS `crust build` leaves the flat Mach-O at `dist/crust-app` beside the `.app`; `appImageOptions` points `buildAppImage` at that file, so if `appimagetool` is installed the command produces a `ok: true` AppImage containing a Mach-O that cannot execute on Linux. Symmetrically, the default format `dmg` on Linux/Windows reaches `buildDmg`, whose `isDirectory()` check rejects the flat binary with the false advice "run the build and sign steps first" (`src/packaging/dmg.ts:30-36`) — the build did succeed.
- reachable by: on macOS, `crust package --format appimage` (with `appimagetool` on PATH) → an AppImage that installs but exits with exec-format error on Linux. On Linux/Windows, bare `crust package` → the misleading failure.
- smallest fix: reject a format whose target platform differs from `process.platform` in `parseFormats`/`packageCommand` with a clear "cross-compilation not supported" message, before any builder runs.

## Checked and clean
- **Info.plist / deep links** (`src/packaging/plist.ts`, `src/packaging/deep-link.ts`): read. All six `REQUIRED_PLIST_STRINGS` plus `CFBundleVersion`, `NSHighResolutionCapable` and both ATS keys are emitted; values are XML-escaped; `mergeDeepLinkPlist` anchors on `</dict>\n</plist>` and cannot append outside the root dict; scheme validation rejects reserved and non-RFC schemes before the plist is written.
- **Hardened runtime entitlement** (`src/packaging/entitlements.ts`, `src/packaging/sign.ts`): read. Both `com.apple.security.cs.allow-jit` and `com.apple.security.cs.allow-unsigned-executable-memory` are sealed when `hardenedRuntime` is set; the temp plist is removed in `finally`. The known "signs but never creates a page" trap is covered.
- **DMG command syntax** (`src/packaging/dmg.ts`): measured against local `diskutil image create from` help — `--format UDZO --volumeName <name> <source> <dest>` is valid; stage dir removed in `finally`; `hdiutil -ov` fallback is guarded.
- **codesign on non-Mach-O sidecars**: measured. `codesign --force --sign - --timestamp=none` on both a shell script and an arbitrary blob exited 0 here, so the ad-hoc sidecar loop does not fail on script sidecars (the installers test fixture's `bin/tool.sh` is safe).
- **NSIS / AppImage sidecar staging and manifest** (`src/packaging/installers-sidecars.ts`, `src/packaging/nsis.ts`, `src/packaging/appimage.ts`): read. `findInstallerSidecars` reads both flat and `.app` manifest shapes, `stageSidecars` copies into the packaged executable dir, `/oname=` preserves relative paths, and AppImage writes `.DirIcon` plus the root `<id>.png`. No drift between declared names and shipped files in the normal flow.
- **Compile/AOT path** (`src/packaging/build.ts`, `src/packaging/aot.ts`): read. `--trim` always, `--aot` probed once and cleaned up, dynamic-import retry adds `--aot-allow-code-from-disk`; output path is read back so the Windows `.exe` is not guessed.
