# Hunt 20 — `fs` plugin (field 02)

## Critical — Scope escape: `canonical()` collapses `..` lexically, but the OS resolves `..` after a symlink; commands use the raw path
- where: `src/plugins/fs-scope-path.ts:25-38` (`resolve(path)` on line 26 before `realpath` on line 27; the fallback on line 37), plus `src/plugins/fs.ts:101-107` (`scoped()` validates the canonical path but returns the **raw** `value` on line 106). Every command then operates on that raw string: `fs.ts:129-189`.
- mechanism: `canonical()` calls `resolve(path)` first, which folds `a/link/../b` into `a/b` **without following `link`**. `scope.check()` therefore validates a different path than the one passed to `Bun.file`/`node:fs`. The kernel resolves components left to right: it follows `link` (a symlink to a directory), then applies `..` to the **link's target**, landing outside the prefix. Because the raw path is used for the operation, the check passes and the I/O lands outside the grant. The divergence also applies to every other path command (`stat`, `list`, `rename`, `remove`, `mkdir`, `readBinary`, `writeBinary`) — any of them can be aimed outside the scope.
- reachable by: a page that can call any `fs` path command and knows (or learns via `fs.list`, which lists symlinks by name — `fs.ts:151-167`) one in-scope symlink pointing at a directory. It passes a string with `..` after that symlink, e.g. `<scope>/link/../secret.txt`. Measured on darwin against the real plugin with `allow: [<scope>]`: `realpath` of that string resolves to `<outside>/secret.txt`; `stat`, `readTextFile`, `writeTextFile`, `writeBinary`, `rename` (source and destination), and `remove` all **succeeded** on the out-of-scope file, reading `TOPSECRET`, overwriting it with `PWNED`, moving a file outside, and deleting a file outside. `readTextFile` returning the secret proves a full arbitrary file read; the write/rename/remove results prove arbitrary write and delete as the user. Relative paths and the dangling-symlink path are not safe either: the same raw-path/canonical-path split is the root cause. The only precondition is a directory symlink inside the granted scope — ordinary in app data dirs (bundlers, sync folders, host-created links) and discoverable through `fs.list`.
- smallest fix: make the checked path the path that is used. Have `scoped()` return the canonical path and pass that to the I/O call, and never let `resolve()` collapse `..` before symlink resolution — resolve symlinks component-by-component (or `realpath` the full raw string and refuse when it fails for a path that must exist) so the operation cannot land somewhere the check did not validate. Add a regression test asserting that `<scope>/link/../outside-file` is refused for every path command.

## Medium — Recursive `remove` of a parent directory deletes the scope store, despite "no page command may touch it"
- where: `src/plugins/fs.ts:178-182` (`remove` → `rm(target, { recursive })`), contrasted with the store guard in `src/plugins/fs-scope.ts:128-136` (line 131 checks only `samePath(target, store)`), and the design promise in `fs-scope.ts:14-20`.
- mechanism: the store guard compares only the exact addressed path to `scope.json`. It never checks whether a recursive deletion of an ancestor would encompass the store. `remove({ path: <data root>, recursive: true })` passes the guard (the root is in scope and is not the store file) and `rm` then deletes the whole tree including `scope.json`.
- reachable by: a page whose granted scope includes the data directory that holds `scope.json` (the ordinary shape the tamper tests describe). Measured: created a plugin with `allow: [data], root: data`, wrote a grant list to `data/scope.json`, called `remove({ path: data, recursive: true })` — it returned `{ removed: true }` and `data/scope.json` no longer exists. Effect: the host's persisted grant list is destroyed; on the next launch a persisted-only scope becomes empty (a narrowing, **not** a widening — config-provided `fs.scope` prefixes are unaffected). Still contradicts the stated invariant and loses host state.
- smallest fix: before a recursive `remove`, refuse when the canonical store path is contained by the target (`contains(canonical(target), await store())`), or relocate `scope.json` outside any page-grantable directory.

## Checked and clean
- **Plain `..` traversal without a symlink** (`fs-scope.test.ts:96-116`): `canonical()`'s `resolve()` folds `<scope>/../elsewhere` to the real outside path, and `contains()` refuses it. Reproduced conceptually by reading the code; the escape above specifically requires the OS to apply `..` *after* following a symlink, which lexical folding cannot model.
- **Dangling symlinks** (`fs-scope-path.ts:25-38`, `fs-scope-dangling.test.ts:39-72`): `canonical()` reads the link target via `readlink` and resolves it, and `seen` bounds cycles — in-scope dangling links to outside targets are refused. The `..` escape above is a different mechanism and is not fixed by this handling.
- **Symlink size leak via `list`/`stat`** (`fs.ts:114-124`): `entrySize` runs `scope.check()` on a symlink's full path and reports 0 for out-of-scope targets; the throw is swallowed, so only the link's name is exposed, never target content. Confirmed by reading `fs-scope-dangling.test.ts:75-121`.
- **`scopeAllow`/`scopeRevoke`** (`fs-scope.ts:138-182`): `scopeAllow` is refused before argument parsing unless the host opts in with `grants: "page"` (an explicit, documented widening); `scopeRevoke` can only remove grants. Neither widens a default boundary. Read, not measured.
- **Windows drive letters / UNC paths** (`fs-scope-path.ts:41-56`, `fs.ts:151-189`): containment relies on `realpath` canonicalisation with `node:path` `sep`; `samePath` folds case on win32/darwin. No runtime observation was possible here (darwin only), so this is a code read, not a measurement; no concrete hole identified beyond the platform-independent `..` bug above.
- **Tagged base64 validation** (`fs-binary.ts:45-70`): charset plus length-mod-4 validation rejects malformed `__crustBytes` payloads; `Uint8Array` passthrough is correct. Read, not measured.
