# Windows platform hunt (round 2)

All claims are `read` unless marked `measured`. The only measurement was a local arithmetic probe of
the `SetWindowPos` flag word; nothing here can run user32, COM or WebView2.

## High — `SHIM_SWP_FRAME_ONLY` is `0x34`, so every style write moves the window to 0,0 and resizes it to 0×0
- where: `src/platform/windows/shim/11_win32_style.c:53-56`; `src/platform/windows/shim/45_style.c:41-48,72-83`; `src/platform/windows/window-style-adapter.ts:47-56,67-86`; `src/platform/windows/window-fullscreen-adapter.ts:64-81`
- mechanism: `SHIM_SWP_FRAME_ONLY` is defined as `0x0034u` beside a comment saying it is `SHIM_SWP_TOPMOST` (`0x0013` = NOSIZE|NOMOVE|NOACTIVATE) plus `SWP_FRAMECHANGED` (`0x0020`) — which would be `0x33`. `0x34` instead contains `SWP_NOZORDER` (`0x04`) and drops both `SWP_NOSIZE` and `SWP_NOMOVE`. Both callers pass `SetWindowPos(hwnd, 0, 0, 0, 0, 0, SHIM_SWP_FRAME_ONLY)`: with no NOSIZE/NOMOVE the explicit zeroes are the new position and size. `measured`: a local probe printing the decoded bits gave `{NOSIZE:false, NOMOVE:false, NOZORDER:true, NOACTIVATE:true, FRAMECHANGED:true}`.
- reachable by: any `window.setDecorations(label, …)`, `window.setOpacity(label, …)`, `window.setStyle(…)`, or `window.setFullscreen(…)` — all route through `shim_window_set_style` / `shim_window_set_alpha`. For a default window (configured minimum 0×0, because `window-open.ts:98` overwrites the create-size floor with the configured minimum) `WM_GETMINMAXINFO` has no floor, so the window collapses to a 0×0 frame at the primary display origin. For a window with a configured minimum the resize is clamped to that minimum, but the move to (0,0) still happens. The style read-back in `shim_window_set_style` answers 1, so the adapter reports success for a collapsed window.
- smallest fix: change the constant to `0x0033u` (NOSIZE|NOMOVE|NOACTIVATE|FRAMECHANGED), or add `SWP_NOSIZE|SWP_NOMOVE` to the flags at both call sites; add a source assertion that the constant includes `0x1` and `0x2` and excludes `0x4`.

## Medium — a second file pick is parsed as a multi-select from stale bytes left by the first
- where: `src/platform/windows/shim/48_dialog.c:116-126`; `src/platform/windows/shim/48_dialog_paths.c:26-52`; `src/platform/windows/shim/49_dialog.c:19-30,57`
- mechanism: `shim_dialog_reset` clears only `g_dlg_names[0]`, not the 32768-unit buffer. `shim_dialog_split` decides single vs multi by testing `g_dlg_names[first + 1] == 0`, i.e. it expects a second NUL after the path returned by comdlg32. `GetOpenFileNameW` writes the new path and its NUL but does not clear the tail, so bytes left by the previous pick sit at `first+1`. When they are non-zero, the code takes the multi-select branch and builds paths by concatenating the *new* first string with the *old* trailing names.
- reachable by: two picks in one process where the first string is longer than the second — e.g. pick `C:\dir\0a.txt\0b.txt\0\0` with `multiple: true`, then pick a single short file, or simply pick a long path then a short one. The adapter's `answered` only checks each path is non-empty, so bogus paths (a new directory prefix with old filenames) are returned to the page as if picked.
- smallest fix: zero `g_dlg_names` in `shim_dialog_reset` (or set `g_dlg_names[first+1] = 0` after the returned string before the test), and prefer an explicit selection count from `nFileOffset`/API state over a sentinel-byte read.

## Medium — title-bar close permanently consumes a min-size slot, so later windows lose their drag floor
- where: `src/platform/windows/shim/20_class.c:60-67`; `src/platform/windows/shim/44_minsize.c:10-40`; `src/platform/windows/shim/40_window.c:48-52`
- mechanism: the round-20 fix added `shim_webview_close(hwnd)` to `WM_DESTROY` but not the other half of its own recommendation, `shim_window_set_min(hwnd, 0, 0)`. `shim_window_new` records the create size as a min entry for every window; only the TypeScript `destroy()` path calls `shim_window_set_min(hwnd,0,0)` (via `shim_window_destroy`). A title-bar X leaves the entry occupied with a dead HWND. `SHIM_MAX_WINDOWS` is 8 and `shim_window_set_min` silently refuses a new entry once `g_min_count` reaches 8.
- reachable by: create and title-bar-close eight windows, then create a ninth with `minWidth`/`minHeight`. `WM_GETMINMAXINFO` calls `shim_window_min`, finds no entry, leaves `ptMinTrackSize` at Windows' default, and the ninth window can be dragged smaller than its configured minimum. No command reports the constraint was lost.
- smallest fix: call `shim_window_set_min(hwnd, 0, 0)` in the `WM_DESTROY` arm alongside `shim_webview_close(hwnd)`.

## Medium — a close delivered during `handler_wait` still destroys the window under an in-flight WebView2 create
- reachable state carried over from hunt-20 `08-windows.md` finding 2, re-checked and still unfixed: `handler_wait` calls `shim_pump()` with no reentrancy guard, and `WM_CLOSE` in `shim_wndproc` calls `DestroyWindow` directly. A title-bar click during the up-to-5 s environment/controller wait dispatches `WM_DESTROY`, which now also releases the surface slot and posts a quit, while `shim_webview_new` is still on the C stack and later binds a controller to the dead HWND. The nested `TrackPopupMenu` in `shim_tray_menu_open` is a second reentrant dispatcher on the same thread.
- smallest fix: set a pump-reentrancy flag around `handler_wait` (and tray menu) and defer `WM_CLOSE` to a posted message while set; re-check `IsWindow(g_ctrl_hwnd)` after each wait before binding.

## Medium — `screen.list()` still reports `scale: 1` on every high-DPI display
- carried over from hunt-20 `08-windows.md` finding 3, re-checked: `47_screen.c:65` still assigns `entry->scale = 1.0` unconditionally, and `screen.ts:41` turns any non-positive/finite value into 1. A 150% display is reported as 100% with no error. Needs `GetDpiForMonitor` from shcore.dll and a preflight entry.
- smallest fix: load `GetDpiForMonitor` alongside the user32 entries, set `scale = dpi / 96` and fall back to 1 only on failure.

## Low — stale fullscreen record can still be restored onto a reused HWND
- carried over from hunt-20 `08-windows.md` finding 4, re-checked: `window-fullscreen-adapter.ts:64-81` keys `fullscreen` by hwnd and clears it only on the `false` branch. The comment at line 35 reasons only about `isFullscreen`; `setFullscreen(label,false)` still writes the dead window's saved style and frame. With a title-bar close (and Win32 HWND reuse) a new window can inherit them.
- smallest fix: key the saved record by label as well as hwnd, and verify the stored style before restoring.

## Low — an over-long `args` string is silently dropped by the ConPTY spawn
- where: `src/platform/windows/shim/65_pty_open.c:127-138`; `src/platform/windows/pty-conpty.ts:33-41`
- mechanism: `command` is 512 UTF-16 units; the quoted shell is written at `command+1` with cap 510, so `length` can reach 509 and `at = length + 2` can reach 511. `shim_pty_wide(args, command + at, 512 - at)` fails when the args exceed the few remaining units; `if (extra > 0)` then leaves the trailing space with no args at all. `CreateProcessW` starts the shell and the caller gets a normal slot index and pid.
- reachable by: a shell path near the 509-unit cap plus any non-empty `args` — long but legal Windows paths make this a silent loss of the whole argument string rather than an error.
- smallest fix: treat `extra < 0` when `args[0]` is non-empty as a spawn failure with `shim_pty_fail`, or grow the command buffer (keeping the frame under 4096) and reserve a fixed slice for args.

## Checked and clean
- **HRESULT and pointer widths**: every `bun:ffi` declaration matches its C definition's return and argument widths across `ffi.ts`, `ffi-core.ts`, `ffi-dialog.ts`, `ffi-webview.ts`, `ffi-preview.ts`, `notify-tray-ffi.ts` and `keychain-ffi.ts`. The 32-bit HRESULT returns (`CoInitializeEx`, `CoGetApartmentType`, the five preview entries, `CreatePseudoConsole`, `ResizePseudoConsole`, all WebView2 vtable slots and `handler_invoke`'s `code`) are declared `int`, not `shim_i64`, so an undefined high half of RAX/RDX cannot sign-flip a success into a refusal. The genuinely 64-bit `GetWindowLongPtrW`, `ShellExecuteW`, `GetTickCount64` and `VirtualQuery` stay pointer-sized. `GetWindowLongW` is never bound.
- **The `0x34` defect is not pinned by any test**: `window-style-adapter.test.ts` drives a fake shim, and no source assertion reads `SHIM_SWP_FRAME_ONLY`. `frame.test.ts` and `min-size.test.ts` scan frames and the `WM_GETMINMAXINFO` arm respectively. A test that reads the constant and asserts the NOSIZE/NOMOVE bits would have caught it.
- **COM apartment and object lifetime**: `shim_com_init` initialises STA on the Bun thread and `CoGetApartmentType` is read with both out-params present. `handler_addref_object` takes the borrowed completion out-parameter, and the environment/controller/webview references are process-lifetime by policy; `preview_release` releases each QI'd initializer, stream and shell item, and `shim_browser_free` uses `CoTaskMemFree` for getter strings. `wv2_get_source` leaks one BSTR deliberately in a probe path only.
- **HWND lifecycle on the TS path**: `destroyWindow` closes the controller before `DestroyWindow`, and `WM_DESTROY` now releases the surface slot before deciding to post quit; both are idempotent on a missing slot. `windows-registry` prunes on `IsWindow`, and `shim_window_is_open` is a direct `IsWindow` read. Child surfaces are released by their own `WM_DESTROY` when the parent goes.
- **ConPTY handles**: pipe ends handed to `CreatePseudoConsole` are closed on this side; `CreateProcessW` gets `PROC_THREAD_ATTRIBUTE_PSEUDOCONSOLE` by value and `STARTF_USESTDHANDLES` with `INVALID_HANDLE_VALUE`; `shim_pty_close` terminates the child, calls `ClosePseudoConsole`, joins the reader, then closes handles and marks a reader that did not exit as spent without reusing the slot. `ReadFile`/`WriteFile` lengths and `COORD` by value match the kernel32 prototypes, and every ConPTY entry point is in `PTY_PREFLIGHT`.
- **Wide-string conversion and buffers**: `shim_utf16` and `shim_pty_wide` NUL-terminate with `dst[n-1]`, and `shim_utf8` leaves room for the terminator; no local array in the window shim reaches the 4096-byte `__chkstk` threshold (`frame.test.ts` enforces it), and the pty unit keeps two 1024-byte arrays plus its structs under it. The shell command buffer writes stay inside 512 units.
- **32-bit build**: out of scope by design (`10_prelude.c:5`, `c-abi.ts:6-8`); a failed `GetWindowLongPtrW` bind fails closed through `shim_win32_ready()` and `startWindows` before any window call, so there is no silent x86 behaviour.
