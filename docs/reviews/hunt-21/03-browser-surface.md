# Hunt 21 — embedded browser surface

All claims below are `read` unless marked `measured`. No Windows or Linux runtime was observed; those
platforms are read from C and TS only. No hunt-20 predecessor exists for this field.

## High — the origin allowlist stops at `open`/`navigate`; the surface can navigate itself anywhere
- where: `src/plugins/browser-origin.ts:41-62`; `src/platform/darwin/shim/107_navigation.c:86-121`; `src/platform/windows/shim/58_browser_events.c:74-84`; `src/platform/linux/shim/31_browser.c:48-77`
- mechanism: `policy.refusal` is called only by the plugin's `open`, `navigate` and popup reporters. None of the three platforms installs a navigation-policy gate: darwin's `crust_nav_install` delegate implements only did-start/commit/finish/fail, Windows registers only `NavigationStarting`/`NavigationCompleted` (which set a loading flag) and `NewWindowRequested`, and Linux registers only `create` and `permission-request`. Nothing cancels a top-level navigation whose target origin is not in `browser.origins`.
- reachable by: config allows `https://trusted.example`; `browser.open` loads it; the remote document contains `<a href="http://169.254.169.254/latest/meta-data/">`, a `location =` assignment, or a 302 redirect. WebKit/WebView2/WebKitGTK follows it in place. `browser.state` then reports the foreign URL and `browser.capture` photographs foreign content, while the docs (`site/app/docs/guides/browser/page.mdx:3,40`) promise the section names "the origins it may load" and that "naming an origin is the only way one does". The surface carries no bridge token, so this is content spoofing/phishing inside the app window, not IPC escalation — but the stated security boundary does not hold.
- smallest fix: add a navigation decision hook per platform that applies the same `originPolicy.refusal` to every committed navigation and redirect, and cancel/refuse non-allowlisted targets before commit; or narrow the documented claim to "origins the app may point a surface at".

## High — Windows: a failed surface create is reported `ok: true` and aliases the app's own webview
- where: `src/platform/windows/shim/57_browser.c:43-55`; `src/platform/windows/browser-ports.ts:114-121`; `src/platform/windows/browser.ts:98-104`
- mechanism: `shim_browser_surface_new` returns **0** on every failure (`shim_webview_create < 0`, refused watch/popups, refused Navigate); the TS port passes that 0 straight through, and the adapter's failure test is `if (handle < 0)`. Zero is therefore treated as a valid handle. Slot 0 is the app window's own surface (`SHIM_MAX_SURFACES` table, slot 0 reserved by `shim_webview_attach` during window creation), so `p.watch(0)` and `p.refusePopups(0)` install surface handlers on the **app's own** ICoreWebView2, the surface is stored with `handle: 0`, and `open` answers ok. The fake hides this: `src/platform/windows/browser-fake.ts:46` returns `-1` for its refused case, so the unit suite never exercises the real contract (`src/platform/windows/backend-browser.ts:27` documents "or 0 with the surface torn down").
- reachable by: any WebView2 create failure — e.g. open 8 browser surfaces; `shim_webview_create` sees `shim_surface_live() >= SHIM_MAX_SURFACES` (`42_webview.c:99`, 8 slots, slot 0 = app), returns -1, the composite returns 0, and the 8th `browser.open` answers ok. From then on `browser.navigate(label, url)` calls `shim_webview_navigate(0, url)` and navigates the app's own page; `browser:popup` events from the app page are attributed to this surface via `webPointer(0)` matching in `browser.ts:65-67`; `close` destroys the child but never releases slot 0's handlers.
- smallest fix: make the failure sentinel consistent — have `shim_browser_surface_new` return -1 on failure (so the adapter's `< 0` check is real), or test `handle === 0` in `browser.ts` and fix `FakePorts.surface` to return the same sentinel the C returns.

## Medium — macOS: every surface open/close leaks an NSView, WKWebView and configuration
- where: `src/platform/darwin/shim/131_browser.c:50-58`; `src/platform/darwin/shim/30_webview.c:15-33`; `src/platform/darwin/browser-surface.ts:63-76`; `src/platform/darwin/browser.ts:85-104`
- mechanism: `shim_browser_view_new` and `shim_webview_configuration`/`shim_webview_new` return `alloc`/`init` objects at +1. `-addSubview:` retains them and `teardown`'s `-removeFromSuperview` releases only that superview retain; no `release` is ever sent to the WKWebView, its configuration, or the host NSView (rg for `release`/`autorelease` in the darwin browser files and both browser shims finds none, while `110_network.c:73` and `123_snapshot.c:187` show the project's normal release pattern). The UI delegate is retained by association on the webview at `132_browser_ui.c:118`, so it leaks with it. Failed `build()` paths detach the host view without removing/releasing the webview at all (`browser.ts:91,96,102`).
- reachable by: call `browser.open` then `browser.close` in a loop; each cycle strands one WKWebView plus its process and one NSView. Repeated open/close in a long-lived app grows memory without bound.
- smallest fix: send `release` to the webview, configuration and host view in `teardown` and in each failed-build branch (or use autoreleased constructors when the FFI boundary allows); assert the release messages exist in a source-level test as other shims do.

## Medium — Linux: `close` drops the host wrapper from the table without destroying it
- where: `src/platform/linux/shim/42_host.c:20-29,31-47`; `src/platform/linux/shim/30_webview.c:147-154`; `src/platform/linux/shim/41_container.c:164-173`
- mechanism: `shim_webview_close` calls `shim_host_forget(web)` then `gtk_widget_destroy(web)`. The forgotten `GtkFixed` wrapper is the overlay child that held the webview; `shim_host_forget` only zeroes the table entry and never destroys that widget. `shim_container_forget` (window close) likewise forgets the box without walking its overlay children. The webview is destroyed, but an empty, sized GtkFixed stays in the window's overlay.
- reachable by: `browser.open` / `browser.close` in a loop; each close leaves one GtkFixed in the overlay with its last size request and margins, so GTK keeps allocating an invisible child and the table slots recycle onto new wrappers. A later surface at a recycled web address gets a new wrapper, compounding the leak.
- smallest fix: capture the host with `shim_webview_host(web)` before forgetting it and `gtk_widget_destroy` it after destroying the webview; in `shim_container_forget`, destroy remaining overlay wrappers for that window.

## Low — macOS: a refused `-addSubview:` is ignored, so an invisible surface answers ok
- where: `src/platform/darwin/browser.ts:85`; `src/platform/darwin/browser-unit.ts:48,83`; `src/platform/darwin/shim/131_browser.c:67-72`
- mechanism: `shim_browser_attach` returns 1 only when both parent and view are non-null, and the FFI declares it `returns: I32`. The adapter calls it without reading the result, then frames the view, adds the webview, loads and returns ok. A nil `contentView(owner.win)` yields no visible surface with a success answer.
- reachable by: an owner window whose `contentView` send returns 0 (an AppKit window in teardown, or a non-window handle reaching `browserOwner`). Narrower than the other paths because `browserOwner` normally checks window liveness first; a window closing between that check and the send is the concrete interleaving.
- smallest fix: check `shim_browser_attach`'s return like the UI/nav/load statuses and fail with `asFailure` plus a detach.

## Checked and clean
- Origin string handling (`browser-origin.ts`, `src/config/validate-features.ts`): `originOf` uses WHATWG `url.origin`, so lookalike hosts, explicit non-default ports, default-port and case normalisation behave correctly; config rejects path/query/fragment entries. `measured`: ran `bun -e` URL probes for `example.com.evil.test`, `:443`, userinfo, `\@` and IPv6 forms — the comparison is by true origin, not prefix. The gap is navigation *after* the gate, reported above.
- Popup handling (`browser-popup.ts`, all three platform sinks): `target=_blank`/`window.open` are refused in C (`br_new_window` returns nil, WebView2 `put_Handled(TRUE)`, GTK `create` returns NULL), the URL is re-checked against the allowlist before `adapter.external`, and the event carries `handedToOpener` plus the reason. Sinks match the event to a surface by webview pointer and swallow listener throws. One process-wide sink per platform is correct for the one adapter `featurePlugins` builds.
- Bridge-token isolation: each surface gets a fresh `WKWebViewConfiguration` (`browser-ports.ts:41-46`, `shim_webview_new` reuses only the fresh config), a separate WebView2 controller in its own child HWND, or a plain WebKitGTK view; no user scripts, scheme handler or grant table is attached. `read`.
- Popup URL marshalling: fixed 2048-byte C buffers with length-returning readers and `readText`'s two-pass growth; truncation is bounded and NUL-terminated, and a too-long URL is refused on origin before reaching the opener. `read`.
- Surface teardown vs window close: `SurfaceStore.mine`/`close` prune a surface whose owner label is gone and answer `not-found`, not a stale title; Windows WM_DESTROY releases the slot on a title-bar close, Linux `shim_window_destroy` forgets the box, darwin uses the liveness-filtered `windowLabels()`. `read`, and covered by the unit files.
- `capture` honesty: Windows and Linux return typed `not-implemented` naming `ICoreWebView2::CapturePreview` / `webkit_web_view_get_snapshot`; macOS snapshots the surface's own WKWebView via `takeSnapshot(web)`, and `snapshotFrom` rejects zero/negative size, zero scale and empty PNG. `read`.
- `measured`: `bun test src/plugins/browser.test.ts src/plugins/browser-origin.test.ts src/plugins/browser-popup.test.ts src/platform/darwin/browser-adapter.test.ts src/platform/windows/browser.test.ts src/platform/linux/browser.test.ts` → 42 pass, 0 fail. The suite proves the argument/gating shapes and call ordering; it does **not** prove any C-level navigation policy, handle-value contract or ObjC ownership, which is where the findings above live.
- Bounds parsing (`browser-args.ts`): finite-number validation, required positive width/height, nested-or-flat shapes and named refusals are sound; negative x/y are accepted and AppKit/GTK clamp their frame origin. `read`.
