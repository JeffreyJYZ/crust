# Hunt 21 — CLI and packaging commands

## Medium — a failed build leaves a partial `.app`, which `package` and `doctor` both certify as good
- where: `src/packaging/app.ts:83-128` (rm before write; icon step last), `src/cli/util.ts:130-143` (`findAppBundle` checks only `isDirectory`), `src/cli/package.ts:66-71`, `src/cli/doctor/bundle.ts:17-37`
- mechanism: `assembleApp` deletes the existing bundle, copies the binary and writes `PkgInfo`, then converts the icon; a bad icon throws after `Info.plist` would have been written. `findAppBundle` accepts any directory named `<appName>.app`, so a partial bundle satisfies `crust package`, which builds and prints a dmg with exit 0. `checkBundle` likewise reports only a `note` and never checks for `Contents/Info.plist`. A failed rebuild also destroys the previous, valid bundle.
- reachable by: measured — a project with `app.icon` pointing at a 1x1 PNG: `crust build` fails with `icon … is 1x1`, leaving `dist/t.app/Contents/{MacOS/crust-app,PkgInfo,Resources}` with no `Info.plist`. `crust package` then printed `dmg 39.11 MiB … t-0.1.0.dmg` and exited 0. `crust doctor` on the same tree printed `bundle [note] …/t.app` and `all checks passed`.
- smallest fix: write the bundle into a temp dir and rename it into place only after every file exists; have `findAppBundle`/`checkBundle` require `Contents/Info.plist` and `Contents/MacOS/<CFBundleExecutable>` before reporting a usable bundle.

## Medium — repeating a boolean flag silently drops the release stage or the chosen scaffold
- where: `src/cli/argv.ts:43-44` (`translate`), `src/cli/argv.ts:85-90` (`validate`); `src/cli/build/stages.ts:67-68` (`hasStages`)
- mechanism: cac/mri accumulates a repeated flag into an array (`["sign", true, true]` → `raw.sign = [true, true]`). `validate` only refuses `=== true` for value flags and never inspects SCAFFOLDS/STAGE_FLAGS arrays; `translate` only copies a flag when `raw[flag] === true`, so an array is discarded. The command then reports success for work it did not do.
- reachable by: measured — `crust init --react --react` scaffolded the vanilla default (`template templates/default/`); `crust build --dmg --dmg` built a plain ad-hoc app with no dmg and exit 0; `crust build --sign --sign` with `CRUST_SIGNING_IDENTITY` set printed `sign ad-hoc` and `done` with no Developer ID stage. The same drops `--notarize --notarize` and every scaffold flag.
- smallest fix: normalise boolean flags once after parse — accept an array of `true` as `true` (or refuse repeats as a usage error), and have `translate` consume the same normalised value.

## Medium — `doctor` says "bun ok / all checks passed" on a host where `crust build` cannot run
- where: `src/cli/doctor/environment.ts:63` (unconditional `bun` ok), `src/packaging/build.ts:77,81` and `src/packaging/aot.ts:27-30` (spawn bare `bun`)
- mechanism: the `bun` check prints `Bun.version` and `process.execPath` without ever checking that a `bun` executable is reachable on `PATH`, which is how the compile step is spawned. A standalone crust binary with no `bun` on `PATH` therefore gets a clean bill of health while `build` dies with `Executable not found in $PATH: "bun"`. `dev` handles this case via `interpreter()`'s `BUN_BE_BUN` fallback; build does not.
- reachable by: measured — `env PATH=/usr/bin:/bin <bun> src/cli/index.ts doctor` printed `bun [ok] 1.4.5`, `shim [ok]`, `all checks passed`. The same environment's `crust build` printed `crust build: Executable not found in $PATH: "bun"` and exited 1.
- smallest fix: make the `bun` check resolve the interpreter the build will actually use (`Bun.which("bun")` or the compiled binary with `BUN_BE_BUN`) and report `fail` when neither can spawn, or switch the compile step to the shared `interpreter()` helper.

## Low — combined short flags (`-hv`) are parsed by cac but ignored by the CLI's help/version checks
- where: `src/cli/index.ts:86-87` (raw-argv equality checks)
- mechanism: help/version are decided from the raw argv strings before parsing. cac expands `-hv` into `h`, `v`, `help` and `version` keys, but no element equals `-h`/`--help`/`-v`/`--version`, so the branch is skipped. `validate` allows those keys, so the command runs as if no help flag was given.
- reachable by: measured — `crust init -hv` scaffolded a full project and exited 0 instead of printing help; `crust -hv` printed help with no command. cac probe: `["init","-hv"] → options {"h":true,"v":true,"help":true,"version":true}`.
- smallest fix: decide help/version from the parsed `raw.help`/`raw.version` (or test each arg with a `-h`/`-v` prefix-aware cluster matcher) after `cli.parse`, before validation.

## Checked and clean
- **`init` target and asset writes** (read + measured; `src/cli/init.ts:86-152`, `src/cli/assets.ts:41-71`): destinations are `join(target, asset.relative)` where `relative` is produced by `filesUnder` as `path.slice(root.length+1)` or by `embeddedUnder` as a prefix-stripped embedded name — both are relative to the template root, and `join` cannot escape with them. `stat` refuses a file target; a non-empty directory is refused with its entry list; `.DS_Store` is ignored; token substitution is JSON/HTML escaped and skipped for binary files. Measured `init` into a new nested absolute path wrote all eight template files under that path only.
- **Pinned dependency specifier** (read; `src/cli/init.ts:156-177`): checkout → `link:<root>` with backslashes normalised; `x.y.z` → `github:JeffreyJYZ/crust#v<x.y.z>`; a `-dev` version → unpinned GitHub spec. Unchanged from hunt-20 and still correct.
- **Shell interpolation / spawned commands** (read; `src/cli/util.ts:59-81`, `src/cli/build/resolve-assets.ts:27-39`, `src/cli/dev.ts:120-136`, `src/packaging/exec.ts:19-43`): `runShell` and the dev frontend spawn use `cmd: ["sh","-c",command]` with the command taken from the project's own `beforeBuildCommand`/`beforeDevCommand`, not from argv; `cwd` is a separate spawn field. Every other tool invocation uses an argv array (`codesign`, `sips`, `iconutil`, `diskutil`, `hdiutil`, `bun`, `which`, `makensis`, `appimagetool`, `lsof`), so no path is concatenated into a shell string. `quote()` is exported but unused.
- **Bundle assembly and sidecars** (read; `src/packaging/app.ts:60-133`, `src/packaging/build.ts:54-137`, `src/cli/build/sign-adhoc.ts:18-29`): `assembleApp` rejects a missing binary or icon, sets 0755 on the copied executable, and writes `PkgInfo`, `Info.plist` and the sidecar manifest in `Contents/Resources` (so `codesign` does not see nested code). `copySidecars` validates each name with `resolveSidecar` (no absolute paths, no `.`/`..`) before copying; ad-hoc signing signs sidecars before the bundle. The only gap found is the partial-bundle case above.
- **Plist, entitlements and icon content** (read; `src/packaging/plist.ts`, `src/packaging/entitlements.ts`, `src/packaging/icon.ts`): all six required plist strings are written, XML values escape `&<>`; URL-scheme entries go through `mergeDeepLinkPlist`. Hardened entitlements seal both `allow-jit` and `allow-unsigned-executable-memory`, plus audio-input only on opt-in. `readPngSize` checks the PNG signature and the 1024-pixel floor before `sips`/`iconutil`, and always removes the `.iconset`.
- **`supportsAot` probe** (read; `src/packaging/aot.ts:20-40`): writes a scratch entry in `mkdtempSync(tmpdir())`, requires exit 0 and a non-empty output, caches per process, and removes the directory in `finally`. A missing `bun` degrades to plain `--compile` rather than being misreported as AOT support.
- **Notarize and sign stages** (read; `src/cli/sign.ts`, `src/cli/notarize.ts`, `src/cli/build/stages.ts`, `src/packaging/notarize.ts`, `src/packaging/verify.ts`): stage refusal happens before any build work (`--notarize` needs `--sign`, both need darwin, sign needs identity, notarize needs credentials); `runStages` runs sign → notarize/staple → dmg and stops at the first non-zero code. `signStage` verifies with `codesign --verify --strict`; `notarize` treats non-zero submit exit as failure even when stdout holds an `accepted` JSON verdict. No false-success path found here.
- **Doctor checks other than bun/bundle** (read + measured in the clean-PATH run; `src/cli/doctor/*`): platform/arch gate, `sw_vers` floor, config/single detection, `cc()` shim compile, window-module import, bridge bind + one ping on the app's derived port, dev-port/dev-url reachability, backend entry, page-side `.ts` watch note, single-file bundle, source traps, build assets, templates, and native-extension toolchains all produce `fail` statuses counted in the exit code. With bun on PATH the same project reported `all checks passed`; the shim genuinely compiled via `cc()`.
- **Value-flag coercion and `--` separator** (measured; `src/cli/argv.ts:36-38,76-83`): hunt-20's `--dir 123`, `--dir a --dir b` and `crust dev -- app.tsx` reproductions still hold, and `nope --version` still exits 0. These are already reported in hunt-20 and not listed again.
- **Svelte/Vue frontend watch** (read; `src/cli/ignore.ts:15`): `FRONTEND_SOURCE` still lacks `.svelte` and `.vue`, so saving those files under `dev.url` still restarts the runtime. Also already reported in hunt-20 and not listed again.
