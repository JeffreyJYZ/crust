# Preview — hunt 21

Scope: `src/plugins/preview*.ts`, the darwin `QLPreviewPanel` path, the Windows `IPreviewHandler`
path, the Linux refusal, `scripts/e2e-preview.ts`, and the config gate. No hunt-20 predecessor.

## High — the wired preview never gets a window owner, so every window-close teardown path is dead
- where: `src/plugins/preview.ts:98`, `src/plugins/preview-surface.ts:13,73`, `src/platform/darwin/preview.ts:128,159-169`, `src/platform/darwin/shim/128_preview_panel.c:92,95,149-164`, `src/platform/darwin/shim/127_preview_observer.c:60`
- mechanism: `readShow` produces `{path,width,height}` and the plugin passes that object straight to `target.show(request)`. `SurfaceRequest` has no `window` field, and `darwinSurface.show` forwards the same object, so `darwinPreviewAdapter.show` always evaluates `options.window ?? 0` to `0`. The C unit stores that as `preview_owner` and calls `preview_observer_watch(0)`, which returns immediately — no `NSWindowWillCloseNotification` observer is ever installed. All three teardown routes then no-op: `previewWindowClosed(realWindow)` sees `owner() === 0 !== realWindow` and returns without hiding; the pump's `previewOwnerCheck` reaches `shim_preview_owner_live`, which returns 1 immediately because `preview_owner` is 0; and the observer was never registered. The panel is `QLPreviewPanel`, a system singleton that is *not* a child of the app window, so nothing else takes it down when the window goes away.
- reachable by: a page calls `crust.invoke("preview","show",{path})` (the documented and only wired path) in a real window, then closes that window with the red button or `app.window.close`. The panel stays on screen over an empty desktop with no app window to dismiss it; `preview.hide()` is the only thing that clears it, and a closing window never calls it. **measured (JS layer only, no GUI):** driving the plugin with a fake surface shows the request keys are exactly `["path","width","height"]`; driving `darwinPreviewAdapter` with a fake native shows `show owner=0`, `previewWindowClosed(4242)` makes no `hide` call, and `previewOwnerCheck` only reaches `ownerLive`. The C consequences are `read` from the shim.
- smallest fix: thread the calling window's native pointer through the command context into `SurfaceRequest` and `PreviewShowOptions` and have the darwin surface pass it to `adapter.show`. If a window cannot be resolved, refuse `show` rather than installing an ownerless panel that no teardown can find. Add an e2e assertion that closing the window (not calling `hide`) leaves `visible === false`.

## Medium — scope is checked on a canonical path, but the raw string is what QuickLook opens (TOCTOU)
- where: `src/plugins/preview.ts:95,98`, `src/plugins/fs-scope-path.ts:29-43`, `src/platform/darwin/preview.ts:111-115`
- mechanism: `await scope().check(request.path)` resolves symlinks and `..` into a canonical path and authorizes *that*; the return value is discarded. The adapter then runs `absoluteRefusal` (`existsSync`) and `native.setPaths(options.path)` on the original string, and QuickLook later resolves the URL itself. Nothing re-checks the path at open time, and QuickLook can re-resolve/reload the URL long after the check returned. A component swapped between the check and the open changes which file the panel reads without changing the authorized string.
- reachable by: `fs.scope` allows a directory the page (or another same-user process) can write. The page creates `link.txt` there as a symlink to an in-scope document; `preview.show({path: link.txt})` passes containment; before QuickLook opens the URL (or on a later panel reload) `link.txt` is repointed to an out-of-scope secret. The panel now renders data outside the configured boundary. This is `read` — no GUI or race was run here.
- smallest fix: hand the surface the canonical path returned by the scope check rather than the caller's string, and re-check immediately before `setPaths`. Note that even this leaves a window until QuickLook opens the URL; a copied/snapshot file inside the scope is the only fully race-free option.

## Low — every failed macOS show or hide is reported as `not-implemented` / "requires QLPreviewPanel"
- where: `src/plugins/preview-surface.ts:63-80`, `src/plugins/preview.ts:99,113`
- mechanism: `darwinSurface` converts *any* `!outcome.ok` into a `SurfaceRefused` with `requires: "QLPreviewPanel"`, and the plugin converts that to a `not-implemented` capability refusal. `attempt()` in the adapter catches thrown JS/FFI errors and turns them into `PREVIEW_STATUS.refused` with the real message; `shim_preview_show` also returns `noPaths` and `unavailable` for per-file or per-call reasons. The message survives, but the code and `requires` claim the platform has no preview when `QLPreviewPanel` was reachable and the individual request failed.
- reachable by: a page previews a file the panel refuses to render, or an FFI/AppKit call throws; the caller receives `not-implemented` with `requires: "QLPreviewPanel"` and cannot distinguish "this platform cannot preview" from "this call failed". `read`.
- smallest fix: distinguish a capability refusal from a per-call failure — throw a `CrustError` with a `preview-failed` code for `SurfaceRefused`, and reserve `not-implemented` for the platform-absence and `!available()` cases.

## Low — compiled preview unit source is a predictable, never-cleaned temp file
- where: `src/platform/darwin/preview-unit.ts:80-84`
- mechanism: the C source is written to `join(tmpdir(), "crust-preview-<sha256-prefix>.c")` only when the file is absent, then handed to `cc()`. The name is fully predictable from source that ships in the app, the file stays in the per-user temp dir for the life of the machine, and no ownership or content check is made on reuse. A same-user process that plants a file there before the first preview gets its C compiled and its symbols bound inside the app process.
- reachable by: any process running as the same user, before the app's first `preview.show`, writes attacker C to that path. This is `read`; macOS temp-dir permissions limit it to same-user, and the pattern is shared with other compiled units, which is why it is Low.
- smallest fix: create a private per-process temp directory with 0700, write the source there, and remove it after `cc()` returns.

## Checked and clean
- **Path validation and scope policy**: `readShow` requires a non-empty absolute path, both-or-neither positive-integer sizes, and rejects fractions/strings; config `preview.width`/`height` go through `v.positiveInteger` at startup. `scope()` is resolved per call so the runtime's `fs.scope` instance (including runtime-added prefixes) bounds preview, and the scope store's own canonical path is refused. A static symlink or `..` walk out of a prefix is resolved by `canonical` before the check. Nothing here lets a page widen its own boundary. `read`.
- **Config gate**: `featurePlugins` always registers `preview` with the config's default size; no `preview` section is valid and yields panel-default sizing. `validatePreview` has an explicit key allowlist. The Windows and Linux refusals are named `not-implemented` with the missing API, and the bridge turns them into structured errors. `read`.
- **Darwin C ABI and marshalling**: all 14 `bun:ffi` declarations match the C prototypes in arity and width (`shim_preview_owner` as pointer, sizes as `f64`, ints as `i32`); the path bytes are pinned during the call and copied into a static C array, and a one-sided size is ignored. The `??0` fallbacks and reason reads are exception-guarded. `read`.
- **Windows host ABI**: the seven `ffi-preview.ts` declarations match their C definitions (`preview-abi.test.ts` reads the C and checks arity/width), the HRESULT is the one widened `i64` return, and the IIDs/category GUIDs are pinned against the SDK values by `preview-ids.test.ts`. I independently checked the official Windows SDK 10.0.16299 `ShObjIdl_core.idl`: `IPreviewHandler` order is `SetWindow, SetRect, DoPreview, Unload, SetFocus, QueryFocus, TranslateAccelerator`, so `SHIM_PREVIEW_SLOT_UNLOAD 6` is correct. The COM `int`-return rule is documented in `11_preview_decls.c`. `read`.
- **Windows lifecycle**: one preview per process; a second `show` calls `preview_clear()` before resolve/create, every failure path releases the handler and destroys the child HWND, and `shown` with `hwnd === 0` is refused rather than believed. `isFile` refuses directories before any COM call. The Windows host is not reachable through `preview.show` at all — this registration hands it no HWND and answers `not-implemented` by design — so no runtime defect can be claimed here. `read`.
- **Linux refusal**: `linuxRefusal()` names the absent API and points at `opener.openPath`; both commands refuse, and `resolvePreviewSurface("linux")` returns it without loading QuickLookUI or AppKit. `read`.
- **Observability of the teardown bug**: `scripts/e2e-preview.ts` asserts `show`, `hide`, and `outside-scope`, but only ever calls `preview.commands.hide()` — it never closes a tracked window, so the High finding above is invisible to the gate. `read`.
