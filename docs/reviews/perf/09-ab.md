# Perf 09: same-tree A/B of the pump fix

Lane L deliverable. Worktree `~/dev/worktrees/crust/perf-ab`, branch `perf/ab`. Reuses
`scripts/perf/measure.ts` / `in-process.ts` unchanged; no second harness. Own file: this one plus
`ab-*.json` scratch samples in the same `docs/reviews/perf/` directory.

## Verdict

**Ship it, but sell it as frame-time consistency, not as an fps win.** On the identical animating
page, the fixed sources give p50 **17 ms** and p95 **18 ms** in all three runs; pre-fix sources give
p50 **22 ms** every run and p95 **24 ms** twice (34 ms once). The arms do not overlap. The p95 gap
is **6 ms** against a same-arm control spread of **0 ms**. Delivered fps and frames drawn do **not**
improve — after is about 1 fps *lower*, a gap the size of the control spread. No `>50 ms` long frame
appears in any run. The pump claim that survives these numbers is "fewer long gaps", not "more frames".

Every run is **contaminated** (one-minute load 3.74–6.17, global `bun` 13–29, limit 2.0). None is a
clean-machine benchmark. The interleaving and the zero-overlap controls make the directional
frame-time result usable; the fps result is not usable as a win.

## Method

- Same tree, same session, same page, same harness. Only two files change between arms:
  `src/platform/darwin/pump.ts` and `src/platform/darwin/shim/50_app.c`.
  - Before: `git checkout b375ede^ -- <both files>`.
  - After: `git checkout origin/main -- <both files>` (HEAD `0bfeef6`).
  - The harness imports the shim C as text and compiles it through TinyCC per run, so the checkout
    *is* the rebuild; no separate build step exists for this scaffold.
- Harness measures three 3000 ms windows; the table uses the first, **`none`** (page rAF animating
  60 DOM rows + 200 canvas rects, bridge idle — `bridge idle` in `01-baseline.md`). `driver` is
  `requestAnimationFrame`, `visibilityState` is `visible`, frames > 0 in every sample below.
- Occlusion handling copied from the baseline scaffold, unchanged: private
  `_setWindowOcclusionDetectionEnabled:NO` (dev-only, never shipped), public
  `setCollectionBehavior:`, `NSProcessInfo` keep-awake. The harness refuses and deletes a sample on
  zero frames or fps < 10; no run hit that veto.
- Order: **before, after, after, before, before, after**. `after-2` repeats `after-1` with no source
  change; `before-3` repeats `before-2`. Those are the control rows.
- `sysctl -n vm.loadavg` and `pgrep -x bun` are captured by `conditions.ts` at both ends of every run
  and stored in each JSON. Load over 2.0 at either end → `contaminated=true`.
- Probes run under a 40 s shell ceiling; harness app life ≈ 10 s, inside the 15 s probe cap. Cleanup
  runs from `finally` plus exit/SIGINT/SIGTERM/SIGHUP traps. `testing.activation: "none"`, no OS
  screenshot, no cursor or keyboard input, no app activation. Probe PIDs **0 → 0** in every run
  (leak gate PASS); the global `bun` drift is sibling process churn, not a leak from this lane.

### Control spread vs arm delta

| Metric | Before | After | Delta | Same-arm control spread | Inside spread? |
| --- | --- | --- | --- | --- | --- |
| p50 ms | 22, 22, 22 | 17, 17, 17 | −5 | 0 (both arms) | **No** — clean separation |
| p95 ms | 34, 24, 24 | 18, 18, 18 | −6 (vs clean 24) | 0 (after), 0 (before clean) | **No** — clean separation |
| fps | 52.98, 57.83, 57.65 | 56.84, 56.00, 57.15 | ≈ −1 | 0.84 (after), 0.18 (before clean) | **Yes** — no win |
| frames | 159, 175, 173 | 172, 168, 173 | ≈ 0 | 4 (after), 2 (before clean) | **Yes** — no win |

Before-1's p95 34 and fps 52.98 are load spikes; its two repeat rows agree exactly. Using clean rows
only, p95 is 24 vs 18 and fps is ~57.7 vs ~56.7. Either way the p95 delta is outside the control
spread and the fps delta is inside it. Saying "the pump fix raises fps" would be a story, not a result.

## Attribution diagnostic

The fixed shim backs off to a 100 ms pump when AppKit reports every window occluded. This scaffold
reports `occlusionState=8192` (`(state & 2) === 0` → occluded), so that branch can fire in the after
arm. `CRUST_PUMP_STATS=1` exists only on the fixed revision; a diagnostic run printed exactly one
`PUMPSTATS` line (`count=120 tps=50.2 mean=0.763 p95=1.440`) in a ~10 s window, then none — the pump
had dropped below the next 120-tick report. That run failed the harness sanity check
(`one-invoke-per-second fps=0`, no sample written) and is **excluded** from the table; it is evidence
that backoff fired, not a measurement.

To separate backoff from the deadline/slice change, the occlusion early-return was temporarily
removed from `50_app.c` and two more runs were taken, then `origin/main` was restored and verified
clean:

| Diagnostic | p50 ms | p95 ms | fps | frames | load | bun |
| --- | --- | --- | --- | --- | --- | --- |
| `ab-after-nobackoff-1` | 17 | 18 | 56.78 | 172 | 4.78 → 6.17 | 23 → 20 |
| `ab-after-nobackoff-2` | 17 | 18 | 56.67 | 170 | 5.45 → 5.13 | 19 → 21 |

Both match the full after arm. The frame-time delta is carried by the nil event deadline and the
0.25 ms run-loop slice, **not** by the occlusion backoff. Tick cost cannot be compared here:
`CRUST_PUMP_STATS` does not exist at `b375ede^`, so there is no before-arm tick number. Lane E's
6.8 → 2.8 ms tick result stays a separate, cross-branch measurement.

## What is usable

- **Usable, directional:** p50 −5 ms and p95 −6 ms, repeatable across three after runs and three
  before runs in one tree, with zero same-arm spread on the frame-time metrics. Treat as a
  same-conditions A/B under heavy load, not a clean-machine benchmark.
- **Usable, negative:** fps and frames drawn show no improvement. The ~1 fps gap is within control
  spread and in the wrong direction.
- **Not usable:** any absolute fps claim, any tick-cost comparison across revisions, and any claim
  that this isolates the deadline change from the rest of the fix in a frontmost app (the harness
  forces WebKit visible while AppKit still reports occluded).
- All rows contaminated by the brief's load rule. The parent's condition is met honestly: the p95
  delta does **not** land inside the control spread; the fps delta does.
