# Evidence

Everything below was run on macOS 27.0.1, arm64 (M4 Air), Bun 1.4.4+38afee6c8, against `crust` 0.1.12 through 0.1.18, between 2026-11-12 and 2026-11-14. Each row names the script or probe that produced it; a row without one is not here.

## Window

| what was run | result |
| --- | --- |
| `bun run e2e:window`, 61 assertions | four windows through `window.create`: relative `url` resolved against the open window's document, absolute loaded as given, live label refused with `duplicate-label`, closed label re-created with its page loading again, `invalid-size` as a fraction and as zero, `invalid-url` |
| ten launches of the built `examples/hello` bundle, `Contents/MacOS` path | window ordered in at 188.7 ms best, 203.8 ms median, 790.1 ms worst; page's first invoke answered 435.3 ms best, 448.8 ms median, 1.70 s worst |
| idle, four processes, `vmmap --summary` plus `ps` | 101–102 MiB physical footprint for the group; 158–178 MiB `ps` RSS, inflated by shared framework pages |
| 200 invokes on the shipped bridge | 0.067 ms median, 0.475 ms p99 on a reused connection; 0.149 ms / 0.361 ms when each call opens one |
| pump tick delivery over three seconds | a 0.25 ms slice delivered 186 of 187 ticks (99.5%); 4 ms delivered 82.4%, worse than not pumping at all (184 of 187) |
| `-windowNumber` before and after `-close` | 517 both times, one millisecond apart and a second later — hence liveness is `visible \|\| miniaturized \|\| appHidden` |
| a page whose window never appeared | `active no`, `isOnActiveSpace 0` while its JavaScript kept invoking; fixed with `setCollectionBehavior` 257 and `orderFrontRegardless` |

Bridge refusals are measured too: a missing or wrong token is `401`, absent or foreign `Origin` is `403`, own origin is `200`.

## What is not proven

- **Developer ID signing.** No such certificate exists on this machine, so `crust sign`'s path is written and never exercised, and Gatekeeper's behaviour on a recipient's Mac is untested. Ad-hoc is the only signature observed.
- **The free-standing panel at runtime.** A windowless app's `beginWithCompletionHandler:` path has its adapter half tested; the AppKit half has never been entered.
- **A warm first launch, and anything timed from inside the page.** Every cold-start worst case is a cold page cache, and the page's own `ready` marker is resolved but never reported back to the backend, so it is not timed.
