# Evidence

Most rows below were run on macOS 27.0.1, arm64 (M4 Air), Bun 1.4.4+38afee6c8, against `crust` 0.1.12 through 0.1.20, between 2026-11-12 and 2026-11-14. The binary-size and idle-memory rows were re-measured on 0.1.26 on 2026-11-18 and say so. Each row names the script or probe that produced it; a row without one is not here.

## Window

| what was run                                                             | result                                                                                                                                                                                                                                                                              |
| ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `bun run e2e:window`, 64 assertions                                      | four windows through `window.create`: relative `url` resolved against the open window's document, absolute loaded as given, live label refused with `duplicate-label`, closed label re-created with its page loading again, `invalid-size` as a fraction and as zero, `invalid-url`; plus the page's own `innerWidth`/`innerHeight` after the window grew to `1200x760` and shrank to `640x460` |
| ten launches of the built `examples/hello` bundle, `Contents/MacOS` path (0.1.12–0.1.20, 2026-11-12 to 11-14) | window ordered in at 188.7 ms best, 203.8 ms median, 790.1 ms worst of ten; page's first invoke answered 435.3 ms best, 448.8 ms median, 1.70 s worst — a true cold first launch is measured below |
| idle, five new processes, `footprint -p` plus `ps` (0.1.26, 2026-11-18)  | 120.7 MiB physical footprint for the group — main crust 52.0, second crust 8.7, WebContent 21.0, GPU 14.0, Networking 25.0; 252.5 MiB `ps` RSS, inflated by shared framework pages                                                                                                  |

| a person pressed ⌘C, ⌘V and ⌘Q in a built app                            | text copied and pasted in the editor, and the app quit — the menu bar is installed, so AppKit dispatches the standard shortcuts                                                                                                                                                     |

A true cold first launch — cold page cache, `crust` 0.1.26 on 2026-11-18, same macOS 27 arm64 M4 Air — took **1,322.5 ms to window and 1,600.1 ms to first invoke** (`docs/reviews/next-wave/perf.md` §2, spawn/timestamp/kill harness `perf-lane-launch.ts`). The 790.1 ms above is the worst of ten mixed launches on 0.1.12–0.1.20; the ~1.7× gap is cold page cache plus version drift, so the two numbers describe different conditions rather than contradict each other.

Bridge refusals are measured too: a missing or wrong token is `401`, a present and foreign `Origin` is `403`, own origin is `200`, and an absent `Origin` with a valid token is `200` — WebKitGTK's `EventSource` sends none on a same-origin GET, so refusing it killed the whole event stream on Linux while POST kept working.

## What is not proven

- **Developer ID signing.** No such certificate exists on this machine, so `crust sign`'s path is written and never exercised, and Gatekeeper's behaviour on a recipient's Mac is untested. Ad-hoc is the only signature observed.
- **The free-standing panel at runtime.** A windowless app's `beginWithCompletionHandler:` path has its adapter half tested; the AppKit half has never been entered.
- **A warm first launch, and anything timed from inside the page.** Every cold-start worst case is a cold page cache, and the page's own `ready` marker is resolved but never reported back to the backend, so it is not timed.
