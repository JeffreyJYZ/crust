# Logging

A level filter, an append-only file under the app's data directory, and an in-memory ring so a page
reads the tail without touching the disk. Registered on macOS under `logging`.

## write

```js
const result = await window.crust.invoke("logging", "write", {
	level: "warn",
	message: "save took 4.2 s",
});
// { written: true, line: "2026-11-15T…Z WARN save took 4.2 s", path: "…/logs/app.log" }
```

| argument | notes |
| --- | --- |
| `level` | `error`, `warn`, `info` or `debug` |
| `message` | anything; it is stringified into the line |

A line below the configured level is dropped before it reaches the file, and the answer says which of
the two happened:

| answer | meaning |
| --- | --- |
| `{ written: true, line, path }` | the line was formatted and appended |
| `{ written: false, reason: "below-level" }` | the level is quieter than the current one |
| `{ written: false, reason: "bad-level" }` | `level` is not one of the four |
| `{ written: false, reason: "sink-error", line, error }` | the file could not be written; the line is still in the ring |

A write has no failure code: it answers a result every time, so a log call never breaks a caller.

## setLevel and level

```js
await window.crust.invoke("logging", "setLevel", { level: "debug" });
// { level: "debug", changed: true }
```

`changed` is false when the argument was not a level, which tells "ignored" from "applied". `level`
takes no arguments and answers the current name. The plugin starts at `info`.

## tail

```js
const { lines } = await window.crust.invoke("logging", "tail", { limit: 50 });
```

The last `limit` lines of the in-memory ring, capped at 200 and defaulting to the whole ring. It never
reads the file, so it answers instantly and only covers this process's own lines. The file itself is
unbounded and is the record that survives a restart.

## Where the file is

`~/Library/Application Support/<app>/logs/app.log`, where `<app>` is the bundle id the plugin was
built with — `crust` for the default instance the runtime carries.

To name your app, select the other built-ins in `plugins` and mount your own instance, because two
plugins of one name would collide:

```ts
// main.ts
import { createLoggingPlugin } from "crust/plugin";

app.use(createLoggingPlugin({ appId: "land.jyz.notes" }));
```

With `plugins: ["fs", "dialog", "notification", "tray", "window"]`, the mounted instance is the only
one, and its file lands under `land.jyz.notes`.
