# App lifecycle

Six events an app can react to, plus one call that answers what it is.

```ts
import { app } from "crust";

app.on("ready", () => console.log("started"));
app.on("window-all-closed", () => app.quit());
app.on("activate", () => console.log("brought forward"));
app.on("before-quit", async () => {
	await saveDraft(); // AppKit waits for this, up to the platform's own timeout
});
app.on("will-quit", () => console.log("quitting"));
app.on("reopen", () => console.log("clicked in the dock"));

const info = app.info();
// { id, name, version, execPath, packaged }
```

## The six events

| event               | when                                                                                |
| ------------------- | ----------------------------------------------------------------------------------- |
| `ready`             | the platform started and configured windows opened, just before the event pump      |
| `window-all-closed` | every window closed; a listener may still do work, then the app quits               |
| `activate`          | the app became the frontmost application                                             |
| `before-quit`       | termination was requested and has not happened yet — a listener may still do work     |
| `will-quit`         | termination is committed; nothing can stop it now                                    |
| `reopen`            | the dock icon (or the taskbar button) was clicked while the app had no window open    |

`ready` and `window-all-closed` come from the app itself on every platform. The other four come from a platform lifecycle source.

`before-quit` is the only one that can defer. On macOS the app answers `NSTerminateLater` and replies
when every listener has settled, so an `await` inside it really does run before the process ends. A
listener that **throws** is named in the log and never blocks termination — an app that will not quit
because one listener is broken is worse than one that quits and says why.

`will-quit` runs on the way out. It is for the last write that cannot wait, not for anything that
needs a reply.

## `app.info()`

Synchronous, and the same values the bundle and `package.json` carry:

| field      | what                                                                     |
| ---------- | ------------------------------------------------------------------------ |
| `id`       | `app.id` from `crust.config.ts`                                           |
| `name`     | `app.name`                                                                 |
| `version`  | `app.version`                                                              |
| `execPath` | the running executable, which is inside the bundle in a built app          |
| `packaged` | true in a built app, false under `crust dev`                               |

## What each platform does

macOS provides the four native events and the deferred quit. Windows and Linux answer
`not-implemented` naming the notification they would need — Windows `WM_ACTIVATEAPP`, GTK focus
events — rather than emitting an event that never fires. A listener registered on those platforms is
not an error; it simply never hears anything, and the refusal comes from the platform call that would
have supplied the event. `ready` and `window-all-closed` are unaffected: the app emits them itself on
every platform, and a `window-all-closed` listener that throws is named in the log before the app
quits anyway.

`app.info()` works everywhere: it reads the config the process already loaded.
