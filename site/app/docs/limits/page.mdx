# Limits

What crust does not do, stated before you build on it. Each line is a boundary, not a bug list.

## Platform

| limit                       | detail                                                                                                                              |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| macOS 13 (Ventura) or later | the shim links AppKit, WebKit and Foundation by name; the Homebrew formula declares `depends_on macos: :ventura`                    |
| x64 and arm64 only          | no riscv64 — Bun ships no such binary, so there is no target to build even if the platform layer would run                          |
| no Xcode required           | the `.c` shim contains no `#include`; every Objective-C symbol is a hand-written `extern`, so it compiles with an empty environment |
| Linux needs two packages    | GTK3 and WebKitGTK are `dlopen`ed at launch, and the C development package supplies the `libc.so` linker script the shim links against |
| Linux keychain needs a Secret Service | `keychain` uses libsecret's synchronous API, which needs a session bus and a provider (`libsecret-1-0` plus `gnome-keyring` on Debian/Ubuntu); without one, the command refuses with the install line |
| Windows needs WebView2      | it ships with Windows 11 and is an Evergreen update on 10; absent, the preflight says so before the first window                   |
| auto-update needs macOS     | `updater.install` and `updater.relaunch` swap a `.app` and run `open -n`; on Windows and Linux they refuse with `unsupported-platform` |

On Linux, `keychain` talks to libsecret with `secret_password_store_sync` and `secret_password_lookup_sync`. Those calls spin their own GLib main loop, so crust needs none, but they do need a session D-Bus and a running Secret Service provider — `gnome-keyring` on GNOME, or an equivalent — plus an unlocked collection. A headless session has neither, and the command answers `{ ok: false, code: "handler-error" }` naming `libsecret-1-0` and the package to install. There is no plaintext fallback: a secret crust writes to a file it protects itself is `stronghold`'s job, not the keychain's, so Linux credentials that must work without a desktop session belong in file scope.

## Distribution

<Accordion>
  <AccordionItem title="Ad-hoc signing by default">

`codesign --sign -` opens on the machine that built it. `spctl` rejects it with exit 3 and it cannot be notarised, so Gatekeeper refuses it on any other Mac until the recipient runs `xattr -dr com.apple.quarantine "my-app.app"` or right-click → Open.

  </AccordionItem>
  <AccordionItem title="No notarisation without a Developer ID">

A notarised ticket needs a certificate and `notarytool` credentials. `crust sign` takes `CRUST_SIGNING_IDENTITY`, signs with the hardened runtime, and still reports `spctl` refusing until the ticket is stapled.

  </AccordionItem>
  <AccordionItem title="Auto-update is macOS-only">

`updater.check` and `updater.download` are network and hashing only, so they work on every platform. `updater.install` and `updater.relaunch` replace a macOS `.app` bundle and launch it with `open -n`, which have no Windows or Linux equivalent. On those platforms both commands refuse with code `unsupported-platform` and name the platform in the message: an app cannot advertise an update path that can never finish, and there is no silent half-feature.

  </AccordionItem>
  <AccordionItem title="A whole asset directory goes into the binary">

By default `public/`; `build.assets` names a frontend's output instead. A frontend that builds elsewhere needs its own build step first.

  </AccordionItem>
  <AccordionItem title="Next.js means static export">

Route handlers, middleware, ISR, `next/image` optimisation, Server Actions and request-time `cookies()`/`headers()` are out of scope: there is one binary and no server.

  </AccordionItem>
</Accordion>

## No bundled Chromium

The WebView is the system `WKWebView`, so rendering is whatever that Mac's macOS ships. A platform WebKit bug is not something crust can patch, and a page cannot rely on a browser crust pinned. The honest size claim is "no bundled Chromium", never "as small as Tauri": the ~86 MiB floor is the Bun runtime inside the binary, and Tauri's floor is smaller because it ships no JavaScript engine at all.

## Security

| limit                                          | detail                                                                                                                     |
| ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| the bridge trusts the local user                | it binds loopback and every route that carries or accepts a credential requires the bearer token; the boundary is the OS account |
| the document needs its own token               | the navigation URL carries `?token=`, and a request without it answers `401`, so fetching `/` yields no credential          |
| so another local process can drive the app     | only by reading the token from the app's own launch URL or its `0600` `.crust/dev.json` — anything running as your user can  |
| `Origin` is not the credential                 | an absent `Origin` is allowed on purpose, and a present foreign one is `403`; the token is what decides                     |
| inline scripts need the response's nonce       | `script-src` names a per-response nonce, so a `<script>` injected after parse is refused by the engine                      |

A page from another origin cannot reach the bridge, and a stray process cannot learn the token from the
document, the assets or an invoke error. Neither is a sandbox against code already running as you, and
a token that reaches the page is in the page's own URL and history.

`script-src` is `'self'` plus one nonce per document, and `'unsafe-inline'` is gone: the bootstrap
carries `nonce="…"`, and a tag the page's own markup authored is stamped with the same value before
the parser sees it. That closes script injection into the document, not a payload already running in
it. `style-src` keeps `'unsafe-inline'` — inline styles are everywhere in real templates and a style
is not a script door. A `security.csp` of your own replaces the policy whole; the nonce is still
generated for the bootstrap, so a policy whose `script-src` omits it refuses that script too, and
that consequence is yours.

## Notifications

`notification.notify()` returns `{ delivered, reason }`, and `delivered` is true only when the OS reported success. Four measured rules decide it:

| rule                                             | detail                                                                                                                           |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| a bundle in the system temp directory is refused | the same app delivered from `~/dev` and answered code 1 from `/var/folders`, twice each way                                      |
| a denied identifier is never re-asked            | macOS records the denial; the app answers code 1 forever without a prompt                                                        |
| a denial is reversible                           | System Settings → Notifications → Allow made an identifier that had answered code 1 four different ways deliver, with no rebuild |
| the signature is not a cause                     | ad-hoc and Apple Development both deliver on a fresh identifier                                                                  |

Unbundled, there is no bundle identifier, so the modern notification centre is never entered and `delivered` is false. A first post on a new identifier raises a permission prompt; an unanswered prompt is recorded as a denial, so `notify({ waitMs })` bounds how long it may stay up. `requestPermission` answers `not-implemented` — the notification itself requests authorization.

## When in doubt

`crust doctor` covers the traps that produce a silent failure — a shim that will not compile, a bridge that will not bind, an asset directory a build would embed as nothing. The [evidence page](/docs/evidence) holds what was measured for each claim above.
