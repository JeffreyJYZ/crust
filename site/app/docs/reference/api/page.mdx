# Imports

Three entry points, all real `exports` in `package.json`, so they resolve in an installed project with no build step. Page code imports none of them — a page uses the `window.crust` the bridge injects. `crust/vite` is imported by `vite.config.ts`, never by a page.

## Command namespaces

A page reaches the backend with `window.crust.invoke(plugin, command, args)`, or the two-argument form that routes to `app.invoke`. The 36 built-in namespaces are documented by area, one page each; `updater` joins them when the config has an `updater` section, `pty` when it has a `pty` one ([Pty](/docs/guides/pty)), and `testing` only when the process starts with `CRUST_TEST=1`:

- [`window`](/docs/reference/api-window), `window-state`, `positioner` — a window's life, its remembered frame, and nine placements.
- [`fs`](/docs/reference/api-fs), `store`, `database`, `keychain`, `shell`, `sidecar`, `stronghold`, `pty` — text files and their scope, a JSON key-value file, SQLite, OS-protected secrets, an allowlisted program, a bundled helper process, an encrypted store, and a real terminal ([Pty](/docs/guides/pty)).
- [`dialog`](/docs/reference/api-ui), `notification`, `tray`, `menu`, `clipboard`, `shortcut` — panels, the notification centre, the menu bar, the pasteboard, hot keys.
- [`theme`](/docs/reference/api-desktop), `dock`, `power`, `screen`, `accessibility`, `opener`, `os` — appearance, the dock tile, power state, the displays, the AX trust read, the OS hand-off, machine facts.
- [`app`](/docs/reference/api-app), `autostart`, `logging`, `i18n`, `single-instance`, `deep-link` — backend commands, launch at login, the log sink, the language catalogue, the lock, the launch URL.
- [`navigation`](/docs/reference/api-web), `findinpage`, `downloads`, `network`, `crash-reporter` — the webview's own loads, find, downloads, request rules and crash record.
- [`updater`](/docs/reference/api-updater) — manifest, verified download, bundle swap.
- [`testing`](/docs/reference/api-testing) — drive and observe a running page: a DOM click, typed text, one key, queries, waits and the page's console. Registered only when `CRUST_TEST=1`; anywhere else the name answers `unknown-plugin`.

Each page states every command's arguments, its answer and the failure codes it can return. The bridge-level codes are on the [errors page](/docs/reference/errors).

### Failure status

A command that answers a typed failure value instead of throwing — `{ ok: false, code, message }` from `window`, `tray`, `database`, `updater` and others — is sent with a 4xx/5xx HTTP status chosen from its `code` through the same table `CrustError` uses (`invalid-label` → 400, `unknown-window` → 404, `unknown-adapter` → 501, an unmapped code → 400). The body is unchanged: the envelope is still `{ ok: true, result: … }` and the typed failure is still the resolved `result`, so a page that branches on `result.code` or `result.ok` sees exactly what it saw before and a fire-and-forget `await crust.invoke(...)` is never handed a new rejection. `isCrustInvokeError` stays the guard for the separate *rejection* path; these values are not errors in that sense. What changes is the transport: a caller working at the `fetch` level can now tell a refusal from a success without reading the body.

Every `create*` factory returns a `PluginDefinition`. ## `crust/vite`

The dev-server half of the bridge: it injects `window.__CRUST__` and the page client into the document a dev server serves.

| export             | signature                                       |
| ------------------ | ----------------------------------------------- |
| `crust`            | `crust(options?: CrustOptions): Plugin`         |
| `BRIDGE_URL_VAR`   | `const BRIDGE_URL_VAR = "CRUST_BRIDGE_URL"`     |
| `BRIDGE_TOKEN_VAR` | `const BRIDGE_TOKEN_VAR = "CRUST_BRIDGE_TOKEN"` |

`CrustOptions` is `{ urlVar?: string; tokenVar?: string }`, defaulting to the two constants above.

```ts
import { crust } from "crust/vite";

export default defineConfig({
	server: { port: 5173, strictPort: true },
	plugins: [crust()],
});
```

Serve-only (`apply: "serve"`), and the handshake is read per document request, never at config time. `strictPort` is required: the bridge allows exactly the origin `dev.url` names, so a port that drifts makes every invoke `bad-origin`. With neither variable nor handshake file present it warns once and injects nothing.
