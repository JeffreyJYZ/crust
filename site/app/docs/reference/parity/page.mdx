# Parity with Tauri

Tauri's feature list is cross-platform. crust runs on macOS 13+, Linux and Windows, all three with
the system WebView, so this page compares capability by capability and says plainly what is partial
or absent.

Measured 2026-11-15 against the tree at `v0.1.21`, and the ten plugin rows below it on 2026-11-16. A row marked _same_ means crust ships the
capability; _partial_ names the piece that is absent; _via Bun_ means the backend half already has it
and no page-facing API is needed; _module only_ would mean the plugin exists and is tested but the
runtime does not register it.

A status is what the code does **now**. All six of the newer plugins are registered by the macOS
runtime and exported from the split barrels, so no row carries _module only_; the two _partial_ rows
name a limitation that registration cannot remove.

## Out of scope by design

- iOS and Android targets.
- Tauri's mobile-only features: barcode scanner, biometric, geolocation, haptics, NFC.
- A Rust plugin ABI. crust plugins are TypeScript objects registered on the `App`.

Windows and Linux have a `Platform` each, and both are proven: Linux on real GTK, Windows by a `windows-latest` runner executing `CoInitializeEx`, `RegisterClassExW` and a real WebView2 controller. The status of each is on the [platforms page](/docs/reference/platforms).

## Framework guarantees

Every row above answers "can crust call this surface". These answer a different question — *who is
allowed to* — which a matrix of surfaces cannot show, and which is why the capability model and the
token boundary were both absent from this page for two revisions while the sweep stayed green.

| Tauri                          | crust                                                                                                    | Status    |
| ------------------------------ | -------------------------------------------------------------------------------------------------------- | --------- |
| Security / capabilities        | `security.capabilities` + `security.grants`, checked in the bridge before a handler runs                    | same      |
| CSP                            | `security.csp`, and `DEFAULT_CSP` when absent: no inline script, no evaluated string, no framing           | same      |
| Isolation pattern              | none — there is no second document between the page and the bridge                                         | absent    |
| IPC transport                  | loopback HTTP + bearer token on the navigation URL; Tauri uses a custom scheme with no socket at all        | partial   |
| Command authorisation          | deny by default once `security.capabilities` is set; absent config allows every command, as it always has | same      |
| Typed IPC                      | `typedHost`/`typedClient` over one `InvokeMap`; the names and shapes a host registers are the ones a page may call, checked at compile time | same      |
| Sidecar binaries               | `build.sidecars` copies each binary beside the app at `0755`; `sidecar.spawn` runs one and streams `sidecar-stdout`/`sidecar-exit`; an undeclared name or a path outside the bundle is refused by name | same |
| Window material                | `windows[].material`: `vibrancy` on macOS, `mica`/`acrylic`/`tabbed` on Windows 11 22H2+, `none` everywhere; a platform without the backdrop refuses the name rather than opening a grey window | same |
| Lifecycle events               | `activate`, `before-quit`, `will-quit`, `reopen` as `app.on` events and as `app:*` page events, plus `app.info()` — a platform without the concept answers `not-implemented` naming it | same |
| Screen listing                 | `screen.list`/`screen.primary` — id, primary flag, scale, bounds and work area per display; darwin `NSScreen`, Windows `EnumDisplayMonitors`, Linux GDK monitors, in page pixels like `positioner` | same |
| Power events                   | `power.onSleep`/`power.onLock` push `power:sleep`/`power:lock`; a platform without the notification answers `not-implemented` naming it rather than a listener that never fires | same |
| Devtools in development        | `crust dev` sets `CRUST_DEV_INSPECT`; the window is inspectable only behind that flag, so a built app cannot open one | same |
| Updater signing                | Ed25519 over the manifest, sha256 over every artefact, a swapped-out key refused                          | same      |

Three of these are worth stating plainly rather than in a cell:

- **`partial` on the transport is the honest shape.** Tauri and Butter both register a custom scheme
  on the WebView, so there is no port to ask and nothing to fetch. crust serves the page over
  loopback, which is what lets one code path cover `crust dev` and a built app. The token now rides
  the navigation URL instead of the document body, so a local process can no longer read it, but the
  socket still exists and the boundary is the local account.
- **`absent` on isolation is a real gap**, not a naming difference. Tauri's isolation pattern puts a
  second document between the page and the IPC layer with a key the page cannot read, so script
  injected into the app cannot issue commands. crust has no equivalent.
- **Capabilities are authorisation, not a sandbox.** A window granted `fs:*` can write anywhere its
  scope allows. What the model stops is a page calling what nobody granted it — that is the whole
  claim, and the guides page says so in the same words.

## What this means

- **same** — 45 rows
- **via Bun** — 7 rows
- **partial** — 3 rows
- **absent** — 1 row
- **module only** — 0 rows
- **total** — 56 rows, in three tables: 44 callable surfaces, 6 framework guarantees and the 6 Butter-parity rows

The three partial rows each name their own limitation: find's `matches` is 0 or 1 because `WKFindResult` carries only `-matchFound` and `clear` needs a private selector, and secure storage has no Linux half because libsecret needs a running keyring daemon crust does not bind. Network stopped being partial when `status`/`onChange` joined the interceptor, so the row now answers connectivity as well as interception. Nothing is missing, and the row count is checked by `bun run check:parity`, which pins Tauri's official feature names **and** six framework guarantees. That second list exists because the first one could not see them: Tauri's security model is not a plugin, so a matrix of callable surfaces went green while the capability model was absent for two revisions.

The eighteen rows Tauri has no official plugin for are reported by that check as _unlisted_ rather than missing: they are crust surfaces, measured here, and they do not change what Tauri's own list covers.

The Bun rows are not a shortfall: a page reaches them through the backend it already has, and that is
how Tauri's own macOS column behaves for HTTP, WebSocket and process information too. SQL left that
group when `database` gave a page its own commands.

## Runtime proof

Compiling is not evidence that a surface works. `bun run e2e:parity` builds a real app
(`examples/parity-probe`), launches it, and asserts what it printed — twenty proofs, twenty-seven
assertions:

```

PASS  shortcut-press  shortcut-press delivered: {"accelerator":"command+shift+k"}

PASS  summary         parity: PASS 20/20
e2e:parity: PASS  27/27 assertions
```

- **Menu** — `menu.setAppMenu` builds a bar with a submenu and `Cmd+Shift+K`, then `menu.read()`
  returns what `NSApp.mainMenu` actually holds. The probe resets the bar in a `finally`.
- **Clipboard** — a 1×1 PNG is written to the real `NSPasteboard`, read back through
  `readObjectsForClasses:[NSImage]` and re-encoded: 163 bytes with the correct magic. The pasteboard
  text is saved and restored, and the probe prints `clipboard restored: true`.
- **Window chrome** — `setOpacity(0.75)` and `setDecorations(false)` are each read back through the
  command layer, on a real 240×160 window that is closed before exit.
- **Shortcut** — `RegisterEventHotKey` accepts the pair, and the adapter's `dispatch` seam fires the
  same event a press would carry, which reaches the plugin as `command+shift+k`.

### What even this does not prove

A _physical_ key press reaching the hot key is the window server's table and needs a person and a key;
`dispatch` proves the process-side chain and that the grab was accepted. The probe prints menu titles
only, so AppKit's own accelerator wiring inside the bar is unread. A pasteboard holding both text and
an image comes back as text, because there is no full pasteboard snapshot API.
