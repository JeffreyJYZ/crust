# Parity with Tauri

Tauri's feature list is cross-platform. crust is macOS 13+ on Apple silicon only, so this page
compares against **Tauri's macOS column** and says plainly what is out of scope by design.

Measured 2026-11-15 against the tree at `v0.1.21`. A row marked *same* means crust ships the
capability; *partial* names the piece that is absent; *via Bun* means the backend half already has it
and no page-facing API is needed; *module only* means the plugin exists but no runtime registers it,
so the app mounts it with `app.use`.

## Out of scope by design

- Windows, Linux, iOS and Android targets.
- Tauri's mobile-only features: barcode scanner, biometric, geolocation, haptics, NFC.
- A Rust plugin ABI. crust plugins are TypeScript objects registered on the `App`.

## What this means

Counting the rows above — 32 in all — crust ships **24 outright** and has **8 more available through
Bun** with no extra API. Nothing is partial, nothing is module-only, and nothing is missing; the
row count is enforced by `bun run check:parity`, which pins Tauri's official feature names.

The Bun rows are not a shortfall: a page reaches them through the backend it already has, and that is
how Tauri's own macOS column behaves for HTTP, WebSocket, SQL and process information too.

## Runtime proof

Compiling is not evidence that a surface works. `bun run e2e:parity` builds a real app
(`examples/parity-probe`), launches it, and asserts what it printed — twenty proofs, twenty-seven
assertions:

- **Menu** — `menu.setAppMenu` builds a bar with a submenu and `Cmd+Shift+K`, then `menu.read()`
  returns what `NSApp.mainMenu` actually holds. The probe resets the bar in a `finally`.
- **Clipboard** — a 1×1 PNG is written to the real `NSPasteboard`, read back through
  `readObjectsForClasses:[NSImage]` and re-encoded: 163 bytes with the correct magic. The pasteboard
  text is saved and restored, and the probe prints `clipboard restored: true`.
- **Window chrome** — `setOpacity(0.75)` and `setDecorations(false)` are each read back through the
  command layer, on a real 240×160 window that is closed before exit.
- **Shortcut** — `RegisterEventHotKey` accepts the pair, and the adapter's `dispatch` seam fires the
  same event a press would carry, which reaches the plugin as `command+shift+k`.

### What even this does not prove

A *physical* key press reaching the hot key is the window server's table and needs a person and a key;
`dispatch` proves the process-side chain and that the grab was accepted. The probe prints menu titles
only, so AppKit's own accelerator wiring inside the bar is unread. A pasteboard holding both text and
an image comes back as text, because there is no full pasteboard snapshot API.
